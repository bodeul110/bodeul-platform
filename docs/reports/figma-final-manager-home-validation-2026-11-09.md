# 완성본 매니저 홈 검증

기준일: 2026-11-09. 기준은 #511 병합 후 `dev`의 `65587383c44dcfb1fb05fd4147936fb3b2ca2a83`이며, 작업 브랜치는 `codex/figma-final-manager-home`이다. 이 문서는 `dev` 대상 PR의 로컬 구현·검증 기록이다. 병합·개발/운영 배포를 했다는 의미는 아니다.

## 구현한 내용

- [Figma 매니저 홈 1:7071](https://www.figma.com/design/fqwi44prjEgVFZhaM6LuzS?node-id=1-7071)의 로고, 상단 배경, 인사말, 매칭 현황, 서류 바, 안내 사진, 5탭을 반영했다.
- 진행중·완료·취소는 기존 Core API에서 본인에게 배정된 최대 100건만 집계한다. 화면에 범위를 표시하며, 조회 실패·로딩을 0건과 구분한다.
- 캘린더·매칭 탭은 같은 목록의 날짜·상태 필터를 사용한다. 다른 예약 행에서 현재 동행 가이드를 잘못 열지 않도록 현재 세션과 같은 예약에만 가이드 버튼을 표시한다.
- 기존 동행 가이드, 서류 등록, 완료 이력, 문의, 프로필, 채팅, 로그아웃 진입을 유지했다. 일정 메모는 캘린더에서 기존 저장 메서드를 사용한다.
- 계정 재확인과 화면 복귀 시 재조회하며, 화면 이탈·재조회 전의 응답은 무시한다. 인증·역할 오류 시 이전 이름·집계·목록을 지운다.

설계 판단, 접근성 보완과 원본에 없는 데이터 계약은 [구현 기록](../design/figma-final-manager-home-implementation-2026-11-09.md)에 정리했다. 관리자 웹, Core API 서버, DB, 운영 설정과 의존성 버전은 변경하지 않았다. 사용자 소유의 원래 `D:\BoDeul` 변경도 그대로 보존했다.

## Android 화면 검증

연결된 실기기가 없어 읽기 전용·스냅샷 저장 없는 전용 AVD 2개를 사용하고 검증 후 둘 다 종료했다. 실제 `ManagerActivity`에 debug 전용 합성 Repository를 연결했다. 인증 제공자·서버·DB에는 접속하지 않으며 합성 미리보기 Activity는 release에 포함되지 않는다.

| 환경 | 매니저 18건 + 환자 홈 12건 + 로그인 13건 | 최종 매니저 18건 재검사 |
| --- | --- | --- |
| Android 11 / API 30, 360dp, 720×1280, 글꼴 1.0, 3버튼 | 43건 통과 | 18건 통과 |

| Android 14 / API 34, 375dp, 750×1624, 글꼴 1.0, 제스처 | 43건 통과 | 18건 통과 |

회귀 묶음은 172회이며, 마지막 화살표·동행 버튼 보완 후 매니저 홈만 72회 재검사했다. 같은 케이스를 여러 환경에서 반복한 횟수다. 244개의 서로 다른 테스트를 추가한 것은 아니다.

실행 기준:


### 확인한 경로

- 빈 목록의 실제 0건, 상태별 집계, 취소 필터, 날짜 미확인 항목의 임의 배치 방지.
- 매칭·캘린더 선택 상태와 화면 재생성, 뒤로 가기로 홈 복귀, 홈 재선택 시 재조회.
- 현재 동행 표시, 현재 예약 행의 가이드, 기존 화면의 이동 Intent와 로그아웃 처리.
- 조회 오류·재시도, 매칭 실패와 세션 실패의 분리, 이전 요청의 지연 응답 무시.
- 인증 실패·다른 역할·화면 복귀 시 인증 소실 후 이전 정보 제거.
- 일정 메모 초기값·합성 저장·중복 제출 방지·저장 실패 후 재시도 가능 상태, 프로필 조회 실패 시 빈 편집 차단.
- 실제 안내 대화상자, 필수 글자 대비, 긴 이름·글꼴 확대·상하단 고정 영역과 스크롤 경계.
- 공통 안내 카드 추출에 따른 환자·보호자 홈과 기존 로그인 합성 회귀.

이동 Intent 검사는 기존 대상 화면이 선택되는지 확인한 것이다. 해당 화면의 실제 업로드·채팅 송수신·동행 시작/종료까지 수행한 검증은 아니다.

### 캡처에서 보완한 부분

- 환경 표시가 숨겨졌을 때 알림 아이콘이 로고 옆으로 붙는 문제를 독립 여백으로 수정했다.
- 환자 홈과 같은 Edge-to-Edge 설정과 inset 처리를 적용해 상태바·3버튼·제스처 영역을 구분했다.
- 서류 바의 실제 글자 아래 배경 대비와 파란 강조 문장의 대비를 검사했다.
- 현재 동행 버튼에 Material 위젯의 흰 글자 기본값이 남아 있음을 발견했다. 새 대비 검사에서 실패를 재현한 뒤, 공통 스타일과 일치하는 AppCompatButton으로 바꾸고 4개 환경에서 다시 통과했다.
- 캘린더 내부의 동일 ID 자식과 로그아웃 후 이미 종료된 Activity를 참조하던 테스트 가정을 바로잡았다. 작은 화면의 하단 안내는 실제 스크롤 후 전체 노출을 검사한다.

원본 Figma와 실제 캡처의 상단·하단·활성 동행·큰 글자 화면을 직접 비교했다. 로컬 `.tmp/manager-home-validation/`에 환경별 PNG, 마지막 계측 로그, 전체/최종 실행 결과 JSON이 있다. 소프트웨어 `View.draw()` 전체 콘텐츠 이미지는 실제 그림자·배경과 다르므로 최종 시각 판정에는 시스템 스크린샷을 사용했다. 캡처·합성 사용자 정보는 Git에 넣지 않는다.

## 정적 검사

`lintDebug`는 **기존 NewApi 오류 35건, 경고 261건으로 실패**했다. 오류는 변경하지 않은 보호자 예약 코드의 API 26 `java.time` 사용이며 이번 변경 파일의 새 오류는 없다. 이전 매니저 홈의 include 파라미터 오류는 레이아웃 교체로 사라졌다. 경고에는 새 홈으로 교체되어 미사용이 된 구형 자산과 기존 중첩 레이아웃 경고가 포함된다. 이를 숨기는 baseline·suppress는 추가하지 않았다.

`git diff --check`, 변경 텍스트 30개 파일의 UTF-8, 변경 문서의 로컬 링크 149개 존재 확인이 통과했다. 변경 파일 31개에는 새 원본 메뉴 PNG 1개가 포함된다. 비밀값·환경 파일·의존성 버전 변경은 없다.

## 남은 범위

- 실기기, 개발 Firebase/Core API의 실제 매니저 계정, 실제 배정 목록·일정 메모 저장, 관리자 배정부터 동행 종료까지 종단 리허설은 미수행이다.
- API 24/25 호환성과 기존 lint 오류 해결을 이번 화면 검증으로 대신하지 않는다.
- 캘린더·매칭 하위 화면 전체의 완성본 적용, 미배정 예약 수락·자동 매칭, 채팅방 목록·검색, 프로필 사진, 약관·실제 콘텐츠 공급은 별도 범위다. 완성본과 앱 전체가 일치한다고 보지 않는다.
- `dev` 대상 PR로 검토하며, 운영 배포·DB 변경·계정 변경·병합은 이번 요청에 포함하지 않는다.
