# #448 예약 목록 복귀와 하단 탭 회귀 검증

검증일: 2026-09-29(KST). 기준: `dev`의 `e3d0261`.

후속: 이 수정은 #474로 `dev`의 `7170812`에 병합했다. 아래 당시 미완료였던 합성 예약 전체 동선·실제 IME·OS 모드 검증 결과는 [후속 실기기 기록](issue-448-device-navigation-modes-2026-09-29.md)을 따른다.

## 관찰과 구현

[기존 안전영역 보정](issue-448-navigation-insets-2026-09-27.md) 이후 개발 앱에서도 다음 두 오류를 재현했다.

1. 취소한 예약 상세의 `예약 목록 보기`가 새 예약 작성 화면을 열었다. 완료 예약의 보조 목록 버튼도 같은 동작이었다.
2. 홈에서 일정 탭으로 이동하면 남아 있는 홈 Activity의 선택 표시도 일정으로 바뀌었다. 홈 복귀 후 일정 탭을 다시 눌러도 재선택으로 처리되어 이동하지 않았다.

목록 동작을 `OPEN_HISTORY`로 명확히 하고 `ClientBookingHistoryActivity`로 연결했다. 기존 이력이 있으면 재사용하고 상세를 종료하여 뒤로가기로 다시 상세에 갇히지 않게 했다.

공통 Binder는 다른 Activity를 여는 클릭에서 원래 화면의 선택 표시를 유지한다. 재연결 전에 기존 listener를 해제하고, 복원 상태가 다른 탭을 가리키면 재선택도 실제 이동으로 처리한다. 공통 Router에는 `CLEAR_TOP | SINGLE_TOP`을 적용하여 연속 클릭으로 같은 목적지가 쌓이는 경우도 막았다.

서버·DB·관리자 웹·인증·의존성·4개 탭 구성·매니저 전용 메뉴는 변경하지 않았다. 설계 근거는 [판단 기록](../architecture/decision-log.md#2026-09-29-예약-상세-복귀와-하단-탭-선택)에 남겼다.

## 개발 연결 실검증

같은 기기에 수정된 Debug APK를 데이터 삭제 없이 설치하고, 기존 개발용 환자 로그인 상태에서 확인했다. 실제 OS 설정은 3버튼 방식이며 설정을 바꾸지 않았다.

- 기존 취소 예약 상세의 `예약 목록 보기`가 새 예약 폼이 아니라 예약 이력으로 돌아왔다.
- 예약 이력 → 홈 → 일정·이력 재진입이 정상 동작하고 각 화면의 선택 표시가 일치했다.
- 일정·이력 → 동행방 → 내 정보 → 홈을 이동한 뒤 일정·이력에 다시 들어갔다.
- 예약 이력에서 기기 뒤로가기를 누르면 홈으로 돌아오고 홈 탭이 선택되어 있었다.
- 내 정보 화면의 4개 탭 아이콘·라벨이 OS 내비게이션 위에 모두 보이는 것을 화면으로 확인했다.
- 예약 목록은 검증 전후 모두 9건이었다. 예약 생성·수정·취소와 메시지 전송은 하지 않았다. 종료 시 개발 앱 홈으로 돌려놓았다.

실제 계정 표시가 포함된 화면 원본은 공개 저장소에 추가하지 않았다.
