# Notion 브라우저 대조와 작업 정리

확인일: 2026-09-26

## 확인 범위

사용자가 로그인한 Codex 브라우저에서 아래 원본을 읽고 저장소 코드와 GitHub 이슈·PR에 대조했다. 커넥터의 `API token is invalid` 문제를 해결했다는 뜻은 아니며 무료 플랜의 제한으로 단정하지 않는다.

| 원본 | 이번에 확인한 범위 |
| --- | --- |
| 개발 정책 관련 내용 | 본문과 표시된 전체 토론 패널. 확인한 최신 기획 답변은 9월 9일이며 본문은 9월 13일 반영 기록을 유지 |
| 내부 앱 화면 피드백 | 가이드 첫 진입, 메모 모아보기, 자기 위치, STT 요청. `내부테스트 2`에는 제목만 있고 새 테스트 결과 없음 |
| MVP 개발 명세서 개발팀 통합본 v1.1 | 표시된 본문. 현행 정책과 구형 기술·구현 설명이 함께 남아 있음 |
| MVP 화면별 상세 개발 명세서 v2.2 | 표시된 본문. 접힌 상세 항목 전체를 확인한 것은 아님 |
| 개인정보·민감정보·서류 보유기간 및 파기정책 v1.0 | 데이터별 기간과 접근 회수·파기 기준. 정책의 법적 적합성을 새로 검증한 것은 아님 |

기획 답변으로 확인된 보호자 예약, 내부 STT, 관리자 보안 기준은 유지한다. Figma, 해결된 댓글 이력 전체, 법률 자문 새 회신, 실제 서버·DB·기기 상태는 이번 확인 범위가 아니다. 계정·개인정보·비공개 URL·원본 첨부는 공개 저장소로 복사하지 않았다.

## 판정과 변경

| 항목 | 확인 근거와 판단 | 반영 위치 |
| --- | --- | --- |
| 요금 차이 | 노션 P0-04는 2시간 40,000원, 신청 후 24시간 입금 원칙. 현재 Android와 Core API는 기본 69,000원에 옵션·쿠폰 반영 | #27과 MVP·제품 정합성 문서에 미해결 차이 명시 |
| 결제 구현 수준 | 메인 #394·#397·#405~#407, 관리자 웹 #51·#52에 DB·앱·관리자 코드와 개발 합성 API/DB 검증 기록 존재 | #27의 시뮬레이션뿐이라는 설명을 갱신. MFA·App Check 및 실제 수취 게이트는 유지 |
| 길안내 영상 | #393의 V21 영상 자산 ID·버전·텍스트 fallback 계약은 병합됨. 첨부 영상 표시만으로 권리·비식별·게시 승인을 증명하지 못함 | #391에서 완료된 계약과 남은 플레이어·자산 연결 분리 |
| 내부 STT | 9월 9일 내부 연동 답변 유지. 열린 #443의 debug 타이머는 실제 녹음·파일 저장·공급자 호출이 아님 | #420 본문에 현재 구현 경계 추가 |
| 첫 단계 진입 | #422의 9월 19일 팀원 조사와 현재 resolver는 저장된 stepCode 우선, order 0은 첫 단계 처리 | #422에 조사 결과와 신규·기존 세션 실기기 비교 미확인 기록. 열린 #441의 미리보기와 구분 |
| 오래된 기술 설명 | 4자리 상봉번호·사진 안내·self-accept·Firestore 업무 쓰기·Core API를 거치는 관리자 배정은 현행 기준과 다름 | 제품 정합성 문서에 판정표 추가. 최신 기획 목표와 검증된 기술 계약을 각각 유지 |

가격 근거는 [Android 예상 비용 계산](../../app/src/main/java/com/example/bodeul/ui/booking/BookingPriceEstimator.java)과 [Core API 예약 금액 계산](../../core-api/src/main/java/com/bodeul/core/appointment/DefaultAppointmentService.java)이다. 기존 원장·예약 금액을 소급 변경하지 않고 후속 구현에서 새 예약의 견적·결제 snapshot·옵션·쿠폰·기한 안내를 함께 맞춰야 한다. 제품 목표값을 실제 운영 약관이나 금전 수취 승인으로 사용하지 않는다.

기존 개발 결제 증적은 [관리자 조회·권한 기록](issue-27-admin-payment-integration-2026-09-05.md)과 [관리자 웹 합성 상태 전이 기록](https://github.com/bodeul110/bodeul-admin-web/blob/master/docs/payment-state-preview-validation.md)을 따른다. 이번에 해당 테스트를 다시 실행한 것은 아니다.

## 추적 경계

- #419의 생성 승인 판정은 열린 PR #440에 준비된 상태이며 9월 26일 수정 요청 리뷰가 남아 있다. 이번에는 문서만 추가하고 리뷰 코드 수정·병합은 진행하지 않는다. 저장·API·Android 연결과 기존 보호자 쓰기 차단 해제는 완료되지 않았다.
- #423 메모 모아보기와 #424 자기 위치는 기존 병합·검증 범위가 이미 본문에 반영돼 있어 중복 작업을 만들지 않는다. 남은 화면 왕복·오류 상태 실검증은 이번에 건너뛴다.
- #222 파기·위치, #313 서류, #347 법률, #348 탈퇴, #134 운영 및 관리자 웹 #16 App Check의 안전 게이트는 유지한다. 정책 선택만으로 실행·검증 완료 처리하지 않는다.
- 기존 #27·#391·#420·#422 본문을 갱신하고 새 중복 이슈나 완료 근거 없는 종료 처리는 하지 않는다. Notion 원문과 팀원 댓글은 덮어쓰지 않는다.

## 선택 근거

- 작업 목적: 읽을 수 있게 된 원본의 현재 제품 기준과 GitHub 작업 상태를 맞춘다.
- 선택한 방식: 기획 목표는 날짜가 있는 답변, 구현 상태는 코드·병합·날짜별 검증 기록으로 나누어 문서와 기존 이슈를 갱신한다.
- 대안: Notion의 모든 기술 설명을 우선하면 PostgreSQL·별도 관리자 서버 계약을 되돌리거나 미구현 기능을 완료로 오해할 수 있다.
- 선택 이유: 현재 MVP 규모에서는 남은 차이를 기존 이슈에 모으고 실제 기능 구현과 운영 개방을 별도 작업으로 두는 편이 변경 범위가 명확하다.
- 리스크: 오래된 문구·열린 PR·화면 초안을 완료 증거로 오인하거나 요금 변경으로 과거 원장을 훼손할 수 있어 확인 날짜와 남은 범위를 함께 남긴다.

## 검증

문서 6개의 UTF-8 엄격 디코딩과 대체문자 검사, 상대 링크·경로·앵커 426개, `git diff --check`를 통과했다. #27·#391·#420·#422는 `wlsrjsals110` 인증으로 본문을 갱신한 뒤 API 재조회로 준비한 UTF-8 본문과 일치함을 확인했다. 상태는 모두 열림으로 유지한다.

이번 추가 변경은 문서와 GitHub 작업 본문에 한정한다. 앱·Core API 코드, 의존성, 권한, 결제 설정, 배포·DB 쓰기·파기·실기기 검증은 변경하거나 실행하지 않았다. 기존 루트 작업공간의 수정 사항은 유지하고 PR #440의 관리 작업공간에서 문서 변경만 추가한다. 문서 전용 변경이므로 앱·Core API 빌드는 재실행하지 않는다.
