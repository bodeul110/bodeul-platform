# 신규 예약 MVP 요금 정합성 검증

기준일: 2026-09-28

대상: [#27](https://github.com/bodeul110/bodeul-platform/issues/27)

## 구현한 내용

- [9월 26일 Notion 대조](notion-browser-alignment-2026-09-26.md)의 기본 2시간 40,000원 목표를 Android 신규 견적과 Core API 생성 가격에 반영했다.
- 왕복·이동 보조는 준비 정보로 유지하고 미확정 추가요금·쿠폰 할인은 적용하지 않는다. 신규 쿠폰 선택은 숨기고 서버도 `NONE` 이외의 신규 쿠폰 요청을 거부한다.
- 기존 예약 수정은 저장된 기본요금·옵션·할인·최종금액을 보존한다. 동일 생성 요청의 재시도도 과거 금액을 그대로 반환한다.
- 무통장입금 예약의 결제 수단·이동 조건·쿠폰 잠금을 유지한다. 고정요금으로 바뀌어도 조건 변경을 우회할 수 없다.
- 개별 입금기한이 없으면 24시간 입금 원칙, 임박 예약의 운영자 확인과 계좌 안내 전 송금 금지를 표시한다. 자동 취소·환불이나 과거 예약 기한의 소급 변경은 하지 않는다.

## 변경된 범위

Android 예약 폼·견적·기한 안내, Core API 예약 생성·수정과 회귀 테스트만 변경했다. [설계 판단](../design/mvp-booking-price.md)에 대안과 리스크를 기록했다.

V22 원장 초기화는 예약의 `final_price`를 복사한다. 따라서 새 요금에 migration은 필요하지 않으며, 기존 원장·감사 이력·DB 권한을 변경하지 않았다. 관리자 웹은 원장의 기대 금액을 읽는 기존 계약을 유지하고 별도 저장소 소스는 수정하지 않았다.

## 검증

| 검증 | 결과 |
| --- | --- |
| Core API `check` | 459건, 실패·오류 0건. 과거 쿠폰 포함 생성 요청의 재시도도 검증 |
| Android `assembleDebug assembleDebugAndroidTest testDebugUnitTest` | 빌드 성공, 단위 테스트 305건 실패·오류 0건 |
| Galaxy S24 / Android 16 debug preview instrumentation | 24건 통과. 예약 폼 4건 포함 |
| 릴리스 App Check·개발/운영 경계 | `verifyReleaseAppCheckClasspath`와 환경 경계 4건 통과 |
| 신규 견적 조합 | 앱 편도/왕복·이동 보조·과거 쿠폰 조합은 40,000원. 서버는 허용 이동 조합 6개에서 40,000원이며 신규 쿠폰 2종 거부 |
| 기존 예약 | 69,000원 무통장입금·96,000원 쿠폰 적용 예약의 금액 구성 보존, 재시도 시 신규 생성·재계산 방지 |
| 편집 화면 | 기존 96,000원 표시, 로딩 전후 조건 잠금 유지, 신규 모드 복귀 시 40,000원 표시 |
| V22 정적 계약 | 원장 초기화가 `new.final_price`를 복사하며 요금 상수를 하드코딩하지 않는지 확인. 기존 금액 변경 차단 유지 |

실기기 검증은 Firebase 설정이 없는 Mock/CI debug 빌드의 합성 화면 테스트다. 실제 계정·예약이나 송금은 사용하지 않았다. 로컬 Docker 엔진이 실행 중이지 않아 PostgreSQL에 이 변경을 연결하는 실검증은 수행하지 않았다. 정적 SQL 검사·메모리 Repository 테스트는 실제 DB 적용 검증을 대체하지 않는다.

## 남은 범위

- 이 변경의 PR 리뷰·병합과 별도 개발 배포 후 신규 예약·원장 기대 금액의 실제 연동 확인.
- 개별 `paymentDueAt`의 저장·사용자/관리자 공통 표시와 임박 예약 처리 계약. 이번에는 기한 원칙 안내만 변경했다.
- 인증된 관리자 브라우저의 MFA·App Check를 포함한 입금 확인·검토·환불 상태 전이 검증.
- 운영 명의 계좌·현금영수증·환불 절차와 실제 수취 승인. 이번 작업은 계좌를 노출하거나 결제 쓰기 gate를 열지 않는다.

#27 전체 완료나 운영 전환으로 처리하지 않는다. 기존 예약 데이터, production 설정과 의존성 버전은 변경하지 않았다.
