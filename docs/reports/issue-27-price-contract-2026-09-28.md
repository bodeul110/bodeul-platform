# 신규 예약 가격 계약과 배포 순서 검증

기준일: 2026-09-28

대상: [#27](https://github.com/bodeul110/bodeul-platform/issues/27), 선행 [#470](https://github.com/bodeul110/bodeul-platform/pull/470)

후속: #471은 리뷰 후 `dev`에 병합·개발 배포했다. 9월 29일의 실제 인증 앱 생성·관리자 원장 조회·취소 결과와 미완료 범위는 [실연동 검증 기록](issue-27-live-price-validation-2026-09-29.md)에 구분한다. 아래 내용은 9월 28일 구현 시점의 검증 기록이다.

## 구현한 내용

신규 40,000원 요금이 앱과 서버에 서로 다른 순서로 반영되어도 다른 금액의 예약이 조용히 생성되지 않도록 보완했다. [설계 판단](../design/mvp-booking-price.md#앱서버-배포-순서-보호)에 선택 이유와 한계를 남겼다.

- 새 Android는 `POST /api/appointments/price-confirmed`만 사용하며 `pricePolicyVersion=mvp-fixed-40000-v1`과 폼의 실제 `priceSummary.finalPrice`를 보낸다.
- Core API는 신규 예약 저장 전 현재 계약과 40,000원 일치를 검사한다. 계약 누락·불일치는 409, 정수가 아닌 금액은 400으로 거부한다. 서버가 원장 금액을 결정하는 원칙은 유지한다.
- 새 앱이 구형 또는 롤백 서버를 만나면 404/405 안내 후 중단하며 기존 생성 경로로 우회하지 않는다. 응답 유실 재시도도 같은 경로·본문·요청 ID를 사용한다.
- 기존 생성 경로는 남겨 두되 신규 생성에 동일한 가격 확인을 요구한다. 기존 지문이 일치하는 요청의 재시도는 이 검사보다 먼저 처리하므로 구형 앱의 과거 69,000원·96,000원 예약 결과를 유지한다.
- 조회·수정·취소 경로, 원장·감사 데이터와 역할별 권한은 변경하지 않는다. 가격 정책은 인증 수단이 아니다.

## 변경된 범위

Android 예약 요청 직렬화·재시도·안내 리소스와 가격 상수, Core API 생성 DTO·검사·오류, 관련 회귀 테스트와 API 문서를 수정했다. 관리자는 기존 저장 금액을 읽으므로 별도 관리자 웹 수정은 없다.

DB migration·원격 데이터 쓰기·서버 배포·계좌 안내·실제 입금 및 환불·의존성 변경은 실행하지 않았다. 기존 혼합 작업 트리 대신 전용 작업 트리를 재사용했다.

## 남은 범위

- PR 리뷰와 필수 CI. `dev` 병합 시 Core API 자동 배포가 #470의 새 가격도 포함하므로 같은 후보 앱의 배포 계획을 함께 확인한다.
- 인증된 개발 앱 → API → DB → 관리자 웹의 40,000원 생성·원장 조회 일치와 기존 금액 보존. 이번 단위·MockMvc·합성 계측 결과는 이 실제 연동 검증을 대체하지 않는다.
- #422 실제 신규·재개 세션의 시작 단계, #423 실제 저장·종료 후 접근 경계, #448 예약 생성부터 메뉴 재진입까지의 전체 흐름. 이번에는 합성 회귀만 재확인했으므로 이슈를 닫지 않는다.
- #424 실제 지도 권한 거부·위치 서비스 OFF·시간 초과는 이번 계측에 포함하지 않았다.
- 개별 입금기한 저장·공유와 실제 수취 운영 준비는 #27의 별도 후속 범위다. 운영 배포는 별도 승인 경계를 유지한다.
