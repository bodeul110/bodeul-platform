2026-09-09 기획 답변의 보호자 예약, STT 내부 개발과 관리자 보안 기준을 유지한다. 2026-09-27에는 최신 Notion MVP를 기준으로 내부 테스트 의견을 대조했다. 내부 테스트는 결함·사용성 개선의 참고 자료이며 제품 범위를 자동으로 늘리거나 기존 권한을 완화하는 근거가 아니다. 문서 갱신은 구현·배포 완료를 뜻하지 않는다.

Notion이나 Figma의 `실제 구현` 문구만으로 MVP 완료를 판단하지 않는다. 코드, API, 데이터 계약과 검증 기록이 있는 범위만 현재 구현으로 본다.

## 현재 구현과 최신 MVP 경계

### 1. 계정·역할

- 로그인과 회원가입
- 환자·보호자·매니저 역할 분기
- 권한 안내와 필요 시점 최소 권한 요청
- 매니저 자격 서류 제출, 승인 대기와 심사 결과 확인

### 2. 예약·매칭

- 환자 본인의 예약 생성·조회·수정·취소
- 보호자의 환자 대상 예약 생성과 환자 동의 범위 내 진행·최종 리포트 조회를 새 MVP 범위로 채택. 기존 앱·Core API 계약과의 구현 차이는 [#419](https://github.com/bodeul110/Bodeul/issues/419)에서 추적
- 병원·진료과 검색과 카카오 Local 서버 연동
- 건강·이동 정보와 요청사항 입력
- 관리자 전용 PostgreSQL 배정 함수와 매칭 이후 상태 연결
- 매칭 이후 예약·세션 상태 연결

기존 문서의 환자 본인 전용 예약 생성 계약을 보호자 예약 생성까지 확장하는 것이 새 목표다. 예약 생성 권한과 정보공유 동의는 구분하며, 생성 사실만으로 건강정보·위치·채팅·첨부 전체 권한을 부여하지 않는다. 진행·최종 리포트는 환자의 동의 범위에서만 조회한다. 보호자의 수정·취소 권한을 이번 답변으로 일괄 허용하지 않으며 기존 인가 계약은 변경 구현과 검증 전까지 유지한다.

공통 하단 탭은 `홈 / 일정·이력 / 동행방 / 내 정보`로 유지하고 예약별 참여관계로 접근을 판단한다. 권한 없는 화면은 안내 후 이전 화면이나 홈으로 이동한다. 다중 환자 관리 UI, 상세 환자 전환 UI와 복잡한 딥링크 예외는 MVP에서 제외한다. 의사결정능력이 제한된 환자의 법정대리 예외와 성인 환자 동의 기반 예약 개발은 구분한다.

예약 업무는 Spring Core API를 거치고, 매칭 배정은 관리자 Next.js 서버의 PostgreSQL admin-only 함수가 담당한다. 앱은 PostgreSQL이나 Kakao REST API에 직접 연결하지 않는다.

최신 제품 기준과 현재 서버 계약은 관리자 배정으로 일치한다. 상세 명세에 남은 매니저 선착순 수락은 과거 제안으로 분류하고 MVP 기능으로 추가하지 않는다.

### 3. 동행 수행·리포트

- 병원 가이드 데이터 기반 단계 진행
- 현장 메모, 보호자 공유, 수납·약국·복약 상태 기록
- 최종 동행 리포트
- C13의 최대 300자 동행 일지. 후기는 화면 표현만 포함하며 후기 작성·저장 기능이나 실제 정산을 완료 기능으로 설명하지 않음

최신 Notion MVP는 13단계 사용자 흐름을 기준으로 한다. 실제 앱은 병원 가이드 snapshot의 `stepCode`·순서를 사용하므로 기존 7단계 세션을 일괄 재번호화하지 않는다. 가이드 2는 영상을 사용하는 제품 목표로 정했지만, [#391](https://github.com/bodeul110/Bodeul/issues/391)의 승인된 자산·촬영 및 사용 권리·환자와 의료진 비식별 검수가 끝날 때까지 현재 텍스트 안내를 유지한다.

| 단계 | 사용자용 MVP의 범위 | 범위에 포함하지 않는 것 |
| --- | --- | --- |
| C06 진료 보조 | 수동 질문·메모와 녹음 UI | 실제 환자 음성 수집·STT 결과 자동 반영. 비식별 STT 내부 개발은 #420으로 분리 |
| C07 진료 정리 | UI 중심 안내와 기존 수동 기록 | AI 자동 진료 요약 |
| C08 수납 | 정적 병원 지도 안내와 선택 증빙 업로드 | 지도 API를 이용한 병원 내부 길찾기·실제 결제 승인 |
| C09 약국 찾기 | Kakao 지도 앱 진입 | 앱 내부 약국 검색을 새 필수 기능으로 확대. 기존 Core 장소 검색을 제거하라는 의미도 아님 |
| C10 처방 자료 | 최대 3장 이미지 보관 | OCR·자동 약품 추출 |
| C11 복약 확인 | UI 중심의 수동 확인·기록 | 자동 약품 비교·처방 적합성·용량 판단 |
| C12·C13 종료 | C12 현장 종료, C13 최대 300자 일지·완료 및 리포트 흐름 | 합친 메모로 일지 덮어쓰기, 종료 후 매니저의 원문·채팅 접근 복원 |

정적 지도 시안의 병원명은 실제 예약 전체를 특정 병원으로 고정하는 정책이 아니다. 9월 27일 내부 테스트의 지도 추가 논의 메모는 [대조 기록](../reports/notion-mvp-feedback-triage-2026-09-27.md)에서 관리한다. 지도 방식 변경은 이번 문서 정리에서 확정하지 않는다.

### 4. 진행 공유의 현재 구현

- 환자·보호자·매니저 세션 채팅
- 읽음 상태와 FCM 보조 알림
- 이미지·PDF 다건 첨부
- legacy 매니저 위치 공유 코드: 기본 OFF이며 release·production에서는 고정 OFF
- 매니저 자신의 현재 위치 지도 표시: 단말 안의 일회 확인이며 서버 저장·보호자 공유와 별개
- Supabase Realtime private Broadcast와 재연결 snapshot 복구

이 목록은 현재 코드와 개발 검증 범위이며, 그대로 production MVP에 포함된다는 뜻이 아니다.

예약·세션·채팅·읽음·위치·리포트·후속 처리는 PostgreSQL, 세션 첨부 원본은 Firebase Storage에 둔다. 인증 프로필·지원·매니저 서류 심사 메타데이터는 현재 Firestore를 사용하고, 매니저 서류 원본은 Firebase Storage에 둔다. Firestore의 기존 예약·세션 업무 문서는 rollback 비교용 읽기 경계이며 새 Core 업무 쓰기의 원본이 아니다.

현재 채팅은 참여자의 직접 메시지를 저장한다. 동행 단계에서 자동 생성되는 시스템 이벤트형 동행방은 현재 MVP 채택 범위가 아니다.

동행 채팅은 환자·배정 매니저·`CHAT` 동의를 받은 보호자의 직접 메시지, 본문 최대 2,000자와 읽음·FCM을 현재 계약으로 사용한다. 첨부는 JPEG·PNG·PDF 최대 3개·각 10 MiB이며 보호자는 `CHAT + ATTACHMENT`가 모두 유효해야 이용할 수 있다. `CARE_ENDED`부터 신규 메시지·첨부와 매니저 조회를 차단하고 환자는 보관기간 동안, 보호자는 해당 동의 범위가 유효한 동안 기존 기록을 조회한다.

환자 GPS 좌표를 1분 주기로 공유하는 기능을 제품 목표로 하고 4자리 상봉번호는 사용하지 않는다. 현재 코드는 매니저 단말의 1회·연속 위치를 10초 또는 15m 기준으로 전송하며, 종료 시 `+24시간` 만료와 일 1회 정리 작업은 24시간 안의 최종 삭제를 보장하지 못한다. 환자의 명시적 동의와 즉시 철회, 공유 대상별 인가, 종료·취소 시 즉시 삭제 시도와 실패 재시도를 포함한 24시간 최종 상한을 실제 앱·API·DB에서 종단 검증하기 전에는 production 위치 권한 요청·전송·저장·열람을 모두 `OFF`로 유지한다.

## 화면은 있으나 운영 완료가 아닌 범위

- 카드·간편결제의 실제 PG 승인
- 실제 무통장입금 계좌 노출·수취·입금 확인. 무통장입금은 목표 방식이지만 운영 주체 명의 계좌, 확인 담당자, 환불·노쇼·정산과 사용자 안내가 준비되기 전에는 활성화하지 않는다.
- 취소 수수료, 환불, 노쇼와 초과 시간 추가 결제
- 매니저 수익금 출금과 계좌 정산
- 의사결정능력이 제한된 환자의 대리권 증빙·승인·철회 절차. 성인 환자 본인의 정보공유 동의·철회 계약은 구현됐다.
- production Kakao 키, Cloud Run·Vercel 실제 운영 전환

이 항목은 UI나 상태 필드가 있어도 실운영 기능으로 설명하지 않는다.

무통장입금의 기획 목표는 2시간 40,000원과 신청 후 24시간 이내 입금 원칙이며, 임박 예약은 운영자가 별도로 확인하는 방식이다. Android 신규 견적과 Core API 생성 가격은 40,000원으로 통일하고 미확정 추가요금·쿠폰은 적용하지 않는다. 기존 예약 수정·재시도는 저장된 금액을 유지한다. 개별 기한이 없으면 24시간 원칙과 운영자 확인 안내만 표시하며 마감 시각을 임의 생성하지 않는다. [#27](https://github.com/bodeul110/bodeul-platform/issues/27)의 개별 기한 저장·공유, 실제 브라우저·원장 연동과 수취·환불 검증은 남아 있다. [코드 검증 기록](../reports/issue-27-mvp-price-2026-09-28.md)을 배포 완료나 운영 약관·실제 수취 승인으로 사용하지 않는다.

## 내부 개발에 포함하는 음성 기능

네이버 클라우드 STT 내부 연동, 동행 가이드의 녹음 시작·정지와 정지 시 음성 기록 자동 저장은 [#420](https://github.com/bodeul110/Bodeul/issues/420)에서 구현한다. 실제 환자·의료진 정보가 없는 테스트 데이터로 진행하며, 아직 구현 또는 실제 공급자 연동 완료로 표시하지 않는다.

기존 Spring `core-api/`의 인증·세션·파일 인가 경계를 사용하고 공급자 비밀키는 서버에 둔다. 음성 원본은 비공개 파일 저장소, 처리 상태와 권한 메타데이터는 PostgreSQL로 구분한다. AI 요약·복약 비교·STT 결과의 최종 리포트 자동 반영은 이번 개발 범위가 아니다. OCR은 제외하고 약국 영수증 사진 업로드·저장만 유지한다.

사용자용 MVP의 수동 Q&A와 매니저 메모는 유지한다. 실제 녹음의 동의·고지·병원 규정, 공급자 사용 조건과 보관 기준은 운영 활성화 전에 확인하되 비식별 테스트 데이터 기반 내부 개발 전체를 보류하는 조건으로 사용하지 않는다.

## 사용자용 MVP에서 제외하거나 활성화를 보류하는 범위

- 실제 환자 대상 진료 녹음 수집·STT 공급자 전송. 내부 개발 범위와 구분하며 운영 게이트 전에는 비활성 유지
- 외부 AI를 이용한 진료 요약 자동 생성
- OCR 처방전·영수증 인식
- 자동 약품 비교와 상호작용·용량 판단
- 자동 초과 결제와 환불 집행
- 매니저의 의료적 판단·복약지도 기능
- 별도 SOS, 119·보호자·관리자 자동 연락, 사고보고·사고 전용 상태, 보험·자동 보상
- 동의·철회·인가·파기 종단 검증 전 production 환자 GPS 공유와 이동경로 저장

원본 업로드, 수동 기록과 규칙 기반 표시가 있어도 AI·OCR가 구현됐다는 의미는 아니다.

## 출시 전 게이트

1. 의사결정능력이 제한된 환자의 대리권 증빙·승인·철회 방식
2. 실제 사고 대응 기능을 재도입할 경우 연락·책임·보관·법률·보험 기준
3. 취소·환불·노쇼·초과시간 정책
4. 승인된 개인정보 처리방침과 데이터별 production 파기 설정의 법률 최종 대조
5. production 인프라, App Check, Kakao 키와 rollback 검증
6. 실제 무통장입금의 운영 주체 명의 계좌, 입금 확인, 환불·노쇼·정산과 사용자 안내
7. [#391](https://github.com/bodeul110/Bodeul/issues/391) 가이드 2의 승인 영상 원본, 사용 권리, 비식별 검수와 교체 책임

8. 실제 환자 음성 수집·전송 전 동의·고지·병원 규정, 위탁·국외이전·원본 보관 기간과 공급자 조건 확인
9. [#134](https://github.com/bodeul110/Bodeul/issues/134)의 관리자 역할 승인, MFA·유휴 로그아웃, 임시 권한 즉시 회수·긴급 접근 기록, 감사기록 1년과 접근권한 점검 검증. 정확한 로그아웃 시간과 정기 접근권한 점검 주기는 실제 운영 전에 확정한다.

- 구현 완료는 자동화 검사, 배포 또는 실기기 검증 수준을 함께 기록한다.
- 미결 정책은 [Notion 제품 기준 정합성](notion-product-alignment.md)에서 추적한다.
- 법률·보안·민감정보·비가역 삭제·금전·외부 호환성과 충돌하지 않고 코드나 설정으로 되돌릴 수 있는 기본값은 환경과 무관하게 개발팀이 정한다. 선택 이유와 변경 위치를 남기되 임시라는 이유만으로 이슈를 열어 두지 않는다.
- 실제 사용자 데이터, 권한, 금전, 법정 의무에 영향을 주는 항목은 임시값으로 우회하지 않고 출시 전 게이트를 유지한다.
