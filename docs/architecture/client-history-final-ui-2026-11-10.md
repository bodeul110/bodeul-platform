# 이용내역 최종 UI 적용 판단

## 목적

실제 예약 데이터를 유지하면서 환자·보호자 이용내역 화면을 최종 Figma 구조에 가깝게 맞춘다.

## 선택

- 기존 `BookingRepository.getMyAppointmentRequests` 결과를 그대로 사용한다.
- 서버 상태는 `매칭(REQUESTED)`, `진행(MATCHED·IN_PROGRESS)`, `완료(COMPLETED)`, `취소(CANCELED)` 네 탭으로 분류한다.
- 완료 카드의 별점은 후속 조치를 수정할 수 있는 환자에게만 노출하고, 최종 리포트와 카드 본문은 기존 예약 상세 화면으로 연결한다.
- 공용 예약 카드와 분리한 이용내역 전용 레이아웃을 사용한다.

## 대안과 선택 이유

공용 `item_booking_request.xml`을 직접 바꾸는 방식은 변경량이 적지만 예약 신청 화면의 편집·취소 동작까지 깨뜨릴 수 있어 제외했다. 신청 생성 시각은 현재 도메인 모델에 없으므로 화면을 위해 임의 값을 만들지 않고 생략했다.

## 리스크

병원 사진은 현재 Figma 제공 대표 이미지다. 예약별 병원 이미지 계약이 추가되면 서버 URL을 우선 사용하도록 교체해야 한다. 상태 계약이 늘어나면 탭 매핑 테스트와 빈 상태 문구를 함께 갱신한다.
