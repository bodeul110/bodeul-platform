# 피그마 완성본 예약 입력 화면

## 설계 판단

- 작업 목적: 완성본의 신청자 선택, 단계 표시, 입력창, 고정 버튼을 기존 예약 작성·수정 흐름에 반영한다.
- 선택한 방식: 기존 `BookingRequestDraft`와 저장 경계는 유지하고 신청자·연락처 → 방문 정보 → 건강 정보 → 결제 확인으로 입력을 나눈다. 예약 내역의 조회·수정·취소는 별도 보기로 유지한다.
- 대안: 완성본의 모든 신규 항목을 한 번에 서버·DB까지 추가하거나 기존 긴 폼의 색상만 변경하는 방법을 검토했다.
- 선택 이유: 현재 저장 가능한 항목은 단계형 화면으로 바로 전환할 수 있다. 새 항목을 기존 메모에 합쳐 저장하면 관리자 조회와 이후 계약 변경에서 의미를 잃으므로 그렇게 하지 않는다.
- 리스크: 완성본에만 있는 항목과 기존 계약의 차이가 남는다. 아래 제외 항목을 구현 완료로 간주하지 않는다. 필수 글자는 #510에서 승인한 대비 보완을 유지한다.

## 기준과 범위

- 최우선 디자인: [피그마 완성본](https://www.figma.com/design/fqwi44prjEgVFZhaM6LuzS?node-id=1-2722).
- 확인한 프레임: `1:2722`, `1:6506`, `1:6566`, `1:3303`, `1:6204`, `1:6123`, `1:19886`.
- 흰 배경, 15dp 좌우 여백, Pretendard 20/26 제목, 15/22 라벨, 16/22 입력, 10~12dp 모서리, 2dp 진행 표시를 적용한다. 시스템 상태 표시줄·키보드는 Android가 표시한다.
- 병원 검색·진료과·날짜/시간·만남 장소 선택기는 기존 기능을 재사용한다. 이 하위 선택기와 결제 승인·완료 화면 전체의 완성본 전환은 이번 범위가 아니다.
- 환자 입력은 기존 보호자 연락처 필드를 유지한다. 보호자 선택으로 환자 계정의 권한을 바꾸거나 대리 예약 쓰기 제한을 해제하지 않는다.
- 건강 상태·복약·전달 사항·거동 옵션, 이동·매니저 선호·결제 옵션, 기존 예약 금액 보존은 유지한다.
- 신규 개인정보(나이·키·체중 등), 사전 질문 배열, 별도 만남/병원 예약 시각, 약국, 성년후견 항목은 저장 계약이 없어 입력받지 않는다. 기능 추가 시 Core API·DB·관리자 웹 계약을 함께 변경해야 한다.
- 관리자 웹·Core API·DB·Firebase Rules·의존성 버전은 변경하지 않는다.

## 입력과 권한 보존

- `BookingWizardBinder`는 단계·선택·표시만 담당한다. 입력 검증·견적·저장은 기존 `BookingFormBinder`와 Repository 경계를 유지한다.
- 뒤로 이동·예약 내역 보기·화면 재생성 후에도 미완성 입력, 병원 좌표, 만남 지점과 현재 단계를 복원한다. 연락처·건강 정보는 계정 ID와 역할을 다시 확인한 뒤에만 복원한다.
- 기존 수정 예약은 서버에서 갱신한 상태·금액·쿠폰·무통장입금 잠금을 유지한다. 수정 불가능해진 예약은 과거 초안으로 제출하지 않고 내역으로 돌린다.
- 결제 확인 중 중복 제출을 차단한다. 취소하면 작성 내용은 유지하고, 결제 결과를 받으면 계정을 다시 확인한다. 프로세스 재생성으로 대기 중 초안을 잃은 경우 자동 제출하지 않고 재확인을 요청한다.
- 실제 PG를 새로 연결하지 않는다. 기존 결제 체험·현장 결제 안내와 무통장입금 처리를 유지하며 카드번호·ARS 정보를 받는 화면을 모의 구현하지 않는다.
- 원본 뒤로가기 자산은 기존 `bodeul_final_back`과 해시가 같아 재사용했다. 선택 표시·드롭다운은 원본 SVG를 4배 PNG로 변환했다. 드롭다운의 내보낸 기본 방향은 XML에서 회전해 실제 Figma 화면의 아래 방향과 맞춘다.
- 작은 터치 영역은 48dp 이상으로 확보하고, 필수 글자·힌트·버튼 글자는 승인된 고대비 색상을 사용한다. 키보드·상태바·내비게이션 영역은 실제 Android inset으로 처리한다.

| Lint | 전체 `lintDebug`는 기존 보호자 예약 관련 `java.time`의 API 24/26 호환성 오류 35건으로 실패. 전체 경고 309건이며 이번 변경 파일에 보고된 오류·경고는 0건. 기존 오류를 숨기는 baseline이나 suppression은 추가하지 않음. |

예약 테스트는 입력 검증, 단계 전후 이동, 좌표·만남 지점 보존, 화면 재생성, 기존 96,000원 수정 예약 및 무통장입금 잠금, 계정 변경·로그아웃, 결제 취소·중복 방지·모의 저장 성공을 포함한다. 저장 검사는 합성 데이터의 Mock Repository에 한정하며 실제 예약·결제·권한 변경은 실행하지 않았다.

로컬 증거는 `.tmp/booking-validation/`의 환경별 `instrumentation.txt`와 PNG에 보관한다. 대표 4개 환경의 PNG 40개를 비어 있지 않은 이미지로 검사했고, 예약 검증 중 `FATAL EXCEPTION`·ANR은 없었다. 개인 실기기는 연결되어 있지 않아 사용하지 않았고, 작업용 에뮬레이터만 사용했다. 이번 변경은 `codex/figma-final-booking`에서 `dev` 대상 PR로 검토하며 병합·배포와 구분한다.

## 남은 범위

- 병원/진료과·날짜/시간·만남 장소 하위 선택기, 결제 승인·완료 화면의 완성본 전환.
- 신규 필드와 보호자 대리 예약 생성 흐름의 서버·DB·관리자 웹 계약 확장. 기존 계약 부족을 이유로 완성본 목표에서 제외하는 것이 아니라 후속 구현으로 남긴다.
- 실제 개발 계정·실기기에서 병원 검색부터 예약 작성·수정·취소까지의 연동 검증.
- 기존 보호자 예약 `java.time` 호환성 Lint 오류는 별도 수정 범위다.
- 추가 검사에서 발견한 매니저 메모·복약 라벨의 큰 글자 가독성 실패도 별도로 남긴다.
