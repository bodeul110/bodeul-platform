# 예약 상세 완성본 반영

기준은 `dev`의 `4a07d0b5`와 Figma `fqwi44prjEgVFZhaM6LuzS`다. 이용내역 목록은 #516, 결제 확인·신청 완료는 #521에서 병합됐다. 이번 범위는 목록·완료 화면에서 진입하는 환자·보호자 예약 상세다.

## 설계 판단

- 작업 목적: 예약 상세의 상태·매니저·환자·만남·결제 정보를 완성본과 같은 순서와 시각 체계로 표시한다.
- 선택한 방식: 기존 Repository, 상태별 동작 정책과 진행·리포트 조합을 유지하고 화면 모델, Binder, XML을 재구성한다. Activity는 지도·기존 화면 이동, 인셋, 조회 중 동작 차단과 계정 재확인만 연결한다. 진행·리포트의 상세 정보는 펼쳐 볼 수 있게 유지한다.
- 대안: 사진·인적사항·두 시각·입금 기한·예약 삭제까지 서버 계약과 함께 확장하는 방식도 검토했다.
- 선택 이유: 현재 화면 단위 전환에서는 예약 생성·취소·인가 계약을 유지해야 회귀를 분리할 수 있다. 원본 예시를 실제 예약 데이터로 사용하지 않는다.
- 리스크: 완성본의 사진·주소·나이·키·몸무게·신청/매칭/취소 시각·별도 만남 시각은 현재 응답에 없다. 해당 값은 만들지 않고 실제 병원·진료과·예약 일시와 현재 저장된 정보를 사용한다.

## 계약 보존

- 병원 사진 대신 기존 병원 아이콘을 사용하고, 주소 대신 실제 진료과를 표시한다. 지도는 저장된 좌표 또는 병원 이름으로만 연다.
- 단일 `appointmentAt`을 예약 일시로 표시한다. 신청/취소 시각을 예약 일시로 바꿔 쓰지 않는다.
- 환자만 수정·취소·보호자 공유 설정에 접근한다. 입금 안내는 기존 역할·수단 정책을 따른다.
- 입금대기는 서버의 `AWAITING_DEPOSIT`만 표시한다. 예시 계좌·3시간 기한·자동 환불·예약 삭제는 구현된 기능처럼 표시하지 않는다.
- 상태 새로고침, 단계·가이드, 실시간 정보, 리포트, 평가·정산의 기존 경로를 유지한다. 레거시 위치 공유 기능을 새로 활성화하지 않는다.
- 의존성·SDK·환경 설정·API·DB·운영 배포는 변경하지 않는다.

## 구현한 내용

- 흰 화면, 뒤로가기, 상태·예약번호, 파란 테두리 병원 요약, 매니저·환자·만남·결제 정보 순서로 재구성했다. 실제 입금대기일 때 결제 정보를 환자 정보보다 앞에 놓는다.
- 수정은 만남 정보 옆으로 옮기고 취소 확인, 입금 안내, 보호자 공유, 후기·정산, 리포트·예약 목록의 기존 경로를 유지했다. 병원 위치는 앞선 완료 화면과 같은 저장 좌표·이름으로 외부 지도에 전달한다.
- 매니저 연락처·전달사항·진행 현황·리포트는 접고 펼칠 수 있고 화면 재생성·새로고침에도 펼침 상태를 유지한다. 긴 메모는 생략하지 않는다.
- 글자가 커지면 항목명 칸도 넓히고, 글자 배율 1.5 이상에서는 제목·병원 요약·정보 행을 세로로 배치한다. 버튼과 정보 영역은 고정 높이로 자르지 않고, 시스템 내비게이션 밖에서 스크롤할 수 있다.
- 계정 재확인 전에는 이전 예약 내용을 숨긴다. 사용자·역할이 바뀌거나 초기 조회가 거부되면 이전 상세와 동작을 재사용하지 않으며, 최신 상세·후속 기록을 기다릴 때 버튼을 잠근다.
- 변경은 이 상세 화면과 비공개 debug 계측 진입점에 한정한다. 공용 스타일과 다른 화면 테마는 바꾸지 않았다.

## 남은 범위

이번 변경은 예약 상세 UI 범위다. 이 문서는 로컬 구현·검증 기록이며, 개발 브랜치의 실제 반영 여부는 해당 PR의 병합 상태를 따른다. 배포는 별도 단계다. 동행 진행·리포트·채팅·프로필 화면 전체의 완성본 적용은 [전체 계획](figma-final-app-gap-plan-2026-11-07.md)의 후속 범위다.

실기기에서 실제 환자·보호자 계정으로 예약 목록 → 상세 → 수정/취소·지도 앱 왕복과 서버 반영까지의 종단 검증은 이번에 수행하지 않았다. 에뮬레이터의 합성 저장소 검증을 실제 개발 서버 검증으로 간주하지 않는다.

원본의 병원·매니저 사진, 병원 주소, 새 인적사항, 별도 만남 시각, 상태 전환 시각, 3항목 평가와 취소 내역 삭제는 데이터·API 계약이 필요하다. 임의 값이나 작동하지 않는 버튼으로 대체하지 않았다. 전달사항은 스크롤 안의 펼침 영역으로 제공하고, 별도 채팅 바로가기는 추가하지 않았다.
