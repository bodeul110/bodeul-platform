# 완성본 고객센터·문의 화면

## 설계 판단

- 작업 목적: 피그마 완성본의 고객센터 목록, 문의 작성, 답변 대기·완료 상세를 일반 사용자와 매니저에게 적용한다.
- 선택한 방식: 공통 화면과 상태 모델을 사용하고, 기존 ClientSupportRepository·ManagerRepository의 역할별 문의 저장 계약은 유지한다.
- 대안: 두 화면을 별도로 복제하거나 사진 첨부까지 저장 계약을 동시에 확장하는 방법을 검토했다.
- 선택 이유: 현재 규모에서는 같은 디자인·입력 수명주기를 공유하면서 기존 예약 연결·알림·읽음 처리를 보존하는 편이 회귀 위험이 작다.
- 리스크: 피그마의 사진 첨부는 현재 데이터 모델에 없다. 실제 첨부·업로드를 가장하지 않고 미지원 안내를 표시한다. 기존 문의 유형 코드를 유지하며 저장 성공 후 조회 실패 가능성도 안내한다.

## 변경 범위

| 화면 | 반영 내용 |
| --- | --- |
| 고객센터 목록 | 일반 사용자·매니저 공통 헤더, 전체/답변대기/답변완료 필터, 문의 유형·제목·날짜·상태, 하단 문의 버튼 |
| 문의 작성 | 안내 문구, 역할별 문의 분야 선택, 제목·본문, 입력 조건에 따른 버튼 활성화, 작성 취소 확인 |
| 답변 대기 상세 | 문의 원문과 줄바꿈, 날짜, 원본 로고와 대기 안내 영역 |
| 답변 완료 상세 | 문의 원문, 답변 원문·날짜·담당자, 답변 상태와 배경 영역 |
| 공통 상태 | 로딩·빈 목록·조회 실패·재시도·인증/프로필/권한 안내, 긴 내용 스크롤, 시스템 영역·키보드 대응 |

### 기존 기능과 데이터 경계

- `ClientSupportActivity.createIntent`의 예약 ID·문의 ID와 `ManagerSupportActivity` 진입점을 유지했다. 홈·마이페이지·예약 상세·답변 알림의 기존 호출부를 변경하지 않았다.
- `SupportSource`는 기존 `ClientSupportRepository`, `ManagerRepository`, `BookingRepository`를 연결한다. 환자·보호자의 문의 유형 5개와 매니저의 문의 유형 4개, 제출 인자·저장 위치는 그대로다.
- 예약에서 진입하면 예약을 조회해 연결 ID를 검증한다. 조회 실패 시 연결을 지운 일반 문의로 접수하지 않고 재시도하도록 한다.
- 환자·보호자 답변 알림의 상세 진입과 기존 전체 미읽음 답변 처리 호출을 유지했다. 문의 작성 중 알림은 초안을 닫거나 덮어쓰지 않는다.
- `SupportViewModel`의 `SavedStateHandle`로 초안·문의 분야·필터·상세 선택을 보존한다. 전송 중 재생성은 중복 전송하지 않고, 결과가 불확실하면 목록부터 다시 확인하며 초안을 보존한다.
- 시작·복귀·제출 직전 인증을 확인한다. 다른 계정이나 역할로 바뀌면 이전 초안·선택·예약 연결을 제거하고, 중지된 화면의 지연 인증 응답은 새 접수를 시작하지 않는다.
- 원본의 사진 버튼은 표시하되 미지원 안내만 제공한다. 첨부 선택기·업로드·파일 접근 권한을 추가하지 않았다.
- 서버·DB·Rules·API·권한·의존성·배포 변경은 없다. 관리자 웹의 기존 문의 처리 계약에도 변경이 없다.

### 자산과 표시

- [사진 아이콘 `1:5264`](https://www.figma.com/design/fqwi44prjEgVFZhaM6LuzS?node-id=1-5264)과 [대기 로고 `1:12718`](https://www.figma.com/design/fqwi44prjEgVFZhaM6LuzS?node-id=1-12718)의 원본 벡터를 투명 PNG로 렌더링해 포함했다. 각각 26dp·60dp 프레임의 4배 해상도다.
- 기존 완성본 뒤로가기·드롭다운 자산, Pretendard, 색상 토큰을 재사용한다. 화면별 스타일만 추가해 다른 화면의 테마를 바꾸지 않았다.
- 기본 여백은 15dp이며, 큰 글꼴에서는 고정 높이 대신 최소 높이와 스크롤을 사용한다. 필터·뒤로가기는 48dp 이상 터치 영역을 유지한다.
- 문의 원문과 답변은 상세에서 생략하지 않는다. 목록의 긴 제목만 두 줄로 요약 표시한다.

## 검증

### 자동 검증

| 항목 | 결과 |

| `testDebugUnitTest` | 517건 통과, 실패·오류·건너뜀 0건. 신규 문의 상태/저장소 테스트 24건 포함 |
| `assembleDebugAndroidTest` | 성공 |
| `:app:verifyReleaseAppCheckClasspath` | 성공 |
| `node tools/android/check-environment-boundary.mjs` | Debug/Release의 Core API·Realtime 환경 교차 주입 차단 4건 통과 |
| 기본 화면 회귀 | 고객센터 9건 + 마이페이지·설정 18건 + 환자·보호자 홈 12건 + 매니저 홈 19건, 총 58건 통과 |
| 작은 화면 | 360dp, 글꼴 2.0배, 3버튼 내비게이션에서 고객센터 9건 통과 |
| 제스처 화면 | 412dp, 글꼴 1.3배, 제스처 내비게이션에서 고객센터 9건 통과 |
| `lintDebug` | 실패. 기존 예약 코드 등의 minSdk 24/API 26 호환 오류 35건. 직전 마이페이지 작업의 보고서와 오류 종류·메시지·파일·줄을 대조한 차이는 0건 |

계측은 Android 11/API 30 에뮬레이터에서 수행했다. 기본 화면은 375dp·글꼴 1.0배·3버튼 내비게이션이다. 최종 문의 계측은 3조건에서 각각 9건이며, 기본 조건의 9건은 위 58건에 포함된다. 같은 테스트의 반복 실행을 서로 다른 테스트 수로 세지 않는다.

- 목록 필터·상세·뒤로가기, 역할별 문의 분야·제출 인자, 예약 연결, 읽음 호출, 답변 알림을 검증했다.
- 초안과 상세 선택의 재생성, 작성 취소/계속 작성, 빈 입력·유형 미선택, 전송 중 중복 차단, 실패 후 목록 재확인, 계정 전환·이전 응답 차단을 검증했다.
- 실제 소프트 키보드를 열어 IME 높이가 100dp 이상인지 확인하고, 입력 영역·하단 버튼·시스템 영역이 겹치지 않는지 검사했다. 긴 질문·답변의 마지막 줄까지 스크롤 가능한지도 확인했다.
- 기본/확대/제스처 조건의 화면 캡처 30장을 생성하고 대표 목록·작성·대기·답변·키보드 화면을 원본과 대조했다. 캡처는 합성 데이터이며 로컬 `.tmp/figma-support/captures/`에 보관한다.
- 전체 Lint 성공으로 기록하지 않는다. 이번 레이아웃의 배경과 행 선택 효과에는 `Overdraw` 경고 2건이 남아 있다.

단위 테스트와 계측은 합성 인증·저장소를 사용했다. 실제 계정 로그인, 개발 서버 접수·관리자 답변 왕복, 실기기 검증을 수행했다는 의미가 아니다.

## 남은 범위

- 사진 첨부는 저장·업로드·접근 제어 계약을 별도 구현해야 한다.
- FAQ, 계정·서류 관리 상세 등 다른 화면은 이번 범위가 아니다.
- 실제 개발 서버의 문의 접수·관리자 답변·푸시 왕복과 실기기 확인은 별도다.
- 이 기록은 화면 구현과 로컬 검증 범위다. 개발 반영 여부는 PR 병합 상태를 따르며 운영 배포는 별도다.
