# 매니저 진료 보조 화면 구현 기록

## 목적

현행 Figma MVP의 진료 보조 화면을 Android `CONSULTATION_SUPPORT` 단계에 연결한다. 운영 앱에서는 현재 Core API가 저장할 수 있는 수동 기록만 제공하고, 실제 음성 녹음이나 STT가 준비된 것처럼 보이지 않게 운영 기능과 debug 미리보기의 경계를 분리한다.

## Figma 기준과 단계 교정

- Figma 파일: `NX07k3Tu4cLc6YgAV82RXp`
- 기준 node: `8:1735`
- 화면 제목: `진료 보조 및 기록`

기준 프레임 이름은 동행가이드 6이지만 프레임 내부 단계 배지는 `STEP 03`으로 잘못 적혀 있다. Android는 이 고정 문구를 복사하지 않고 서버 가이드 snapshot의 현재 순번을 동적으로 표시한다. 현재 단계 계약에서 `CONSULTATION_SUPPORT`는 6단계이므로 정상 snapshot에서는 `STEP 06`으로 보인다.

상단 앱바, 단계 배지와 진행 막대, 녹음 원형 버튼, 기록 카드의 시각 위계는 Figma를 따른다. 하단 내비게이션은 Figma 시안의 `일정` 활성 상태를 복제하지 않고 앱 전체 계약에 맞춰 `가이드` 활성 상태를 유지한다.

## 운영 앱에서 제공하는 기능

운영 화면은 기존 세션 PATCH 계약의 다음 두 필드만 편집한다.

| 화면 항목 | 서버 필드 | 최대 길이 | 저장 방식 |
| --- | --- | ---: | --- |
| 보호자에게 공유할 진료 진행 내용 | `guardianUpdate` | 1,000자 | `보호자 공유 저장`으로 개별 저장 |
| 진료 중 확인한 핵심 내용 | `fieldPhotoNote` | 2,000자 | `현장 메모 저장`으로 개별 저장 |

- 두 입력은 의료진 설명, 진행 상황, 검사 결과, 주의사항과 다음 방문 안내를 매니저가 직접 기록하는 자유 텍스트다.
- Figma의 예시 질문 네 개는 실제 세션 데이터가 아니므로 운영 화면에 실제 질문처럼 채우지 않는다.
- 현재 두 서버 필드는 단계별 이력이 아니라 세션의 최신 값이다. 다음 저장에서 이전 값이 교체될 수 있으므로 화면에도 과거 기록이 누적된다고 안내하지 않는다.
- 아직 저장하지 않은 입력은 Activity가 유지되는 동안 ViewModel 메모리에만 둔다. 화면 회전처럼 같은 Activity가 재생성될 때는 같은 세션의 초안을 복원하지만 `SavedStateHandle`, View hierarchy 자동 상태, 파일이나 로컬 DB에는 기록하지 않는다. 두 입력의 Android 자동 View 상태 저장도 명시적으로 끈다. 프로세스가 종료되거나 사용자가 화면을 명시적으로 떠나면 초안은 제거되며, 세션이나 단계가 바뀌어도 다른 환자의 입력이 섞이지 않도록 버린다.
- 서버 재조회가 들어오면 사용자가 수정하지 않은 항목은 최신 서버 값으로 맞추고, 수정 중인 항목만 메모리 초안으로 유지한다.
- 두 저장은 요청을 시작할 때 확인한 세션 ID와 `CONSULTATION_SUPPORT` 단계가 그대로인지 다시 검증한 뒤 전송한다. 저장 또는 단계 이동 중에는 ViewModel의 단일 mutation gate로 후속 mutation을 받지 않아 두 필드 저장과 다음 단계 이동이 겹치지 않게 한다.
- 입력값이 마지막 서버 값과 다르면 다음 단계 CTA를 막고 먼저 각 저장 버튼을 사용하도록 안내한다. 상단 툴바 뒤로가기, 시스템 뒤로가기, 하단의 홈·이력·내 정보 이동에서는 저장하지 않은 내용을 버릴지 확인받고, 버리기를 선택하면 입력을 마지막 서버 값으로 되돌리고 ViewModel 초안을 지운 뒤 화면을 떠난다. 미저장 입력의 저장 mutation이 진행 중이면 이탈을 막고 저장이 끝난 뒤 다시 시도하도록 안내한다.
- 단계 진행 자체는 기존 서버의 `canAdvance`와 `/advance` 판정을 그대로 따른다. 클라이언트가 진료 완료나 단계 통과를 임의로 만들지 않는다.

## debug 녹음 상태 미리보기

`debug` 단계 미리보기에서는 Figma 녹음 영역의 시작, 진행 시간, 정지 상태만 로컬 UI 상태로 확인할 수 있다. 이 영역에는 `DEBUG · 실제 녹음·전송 없음`을 명시하며 운영 빌드에서는 노출하지 않는다.

미리보기는 다음 동작을 하지 않는다.

- 마이크 권한 요청 또는 실제 오디오 캡처
- 음성 파일 생성·기기 저장·서버 업로드
- Naver Cloud API 호출이나 STT 결과 생성
- 화자 분리, AI 요약 또는 보호자 질문 자동 추출

따라서 debug 타이머가 움직이거나 정지 상태가 보이더라도 녹음 파일이 생겼다는 뜻이 아니다. 실제 오디오 저장과 Naver STT 연동은 GitHub Issue #420의 별도 미완료 범위다.

## Figma 자산

기준 node에서 내려받은 원본 캡처와 아이콘은 `docs/design/assets/manager-guide-consultation/`에 보관한다. Android에서는 같은 SVG path를 vector drawable로 옮겨 사용하며, 원본의 녹음·메모·기록 아이콘 의미를 임의로 바꾸지 않는다.

## 검증 기준

- `CONSULTATION_SUPPORT` 진입 시 실제 단계 순번과 전체 단계 수로 배지·진행률이 표시되는지 확인한다.
- 두 입력을 각각 저장한 뒤 재조회 값과 일치하는지, 확인한 세션·단계가 달라진 저장은 거부되는지 확인한다.
- 저장과 단계 이동을 연속으로 눌러도 하나의 mutation만 실행되는지 확인한다.
- 화면 회전에서는 같은 세션의 미저장 초안만 ViewModel 메모리에서 복원되고, 새 Activity·새 ViewModel에 이전 View hierarchy 상태를 적용해도 미저장 문자열이 복원되지 않으며 프로세스 종료·명시 이탈·세션 또는 단계 변경 시 제거되는지 확인한다.
- 미저장 변경이 있으면 다음 단계 CTA가 차단되고, 툴바·시스템 뒤로가기와 하단 내비게이션 이탈에는 버리기 확인이 표시되는지 확인한다. 버리기 뒤에는 ViewModel 초안이 제거되며 해당 입력의 저장 mutation 중에는 이탈이 거부되는지도 확인한다.
- debug 미리보기에서 녹음 시작·정지·화면 재생성 상태만 동작하고 오디오 파일·권한·네트워크 요청이 생기지 않는지 확인한다.
- Step 6에서 다음 단계로 이동하면 Step 7 화면으로 전환되는지 확인한다.

문서 작성 작업은 코드를 실행한 검증으로 간주하지 않는다. 빌드·단위 테스트·debug 계측 테스트와 실제 기기 확인 결과는 해당 PR의 확인 항목에 별도로 기록한다.

## 남은 범위

- 실제 녹음 동의·시작·정지·실패 복구 정책
- 오디오 파일의 비공개 저장소, 보관 기간, 접근 권한과 삭제 절차
- Core API 업로드·메타데이터 계약과 Naver STT 서버 경계
- 실제 제공자 호출을 사용하는 비식별 테스트 음성 검증
- 화자 분리와 AI 2차 가공의 품질·동의·책임 기준

위 항목은 화면 미리보기만으로 완료 처리하지 않으며 Issue #420에서 서버·보안·운영 범위를 함께 구현해야 한다.
