# 환자 예약 메인 Figma 구현 기록

기준일: 2026-09-27

## 작업 목적

한 카드에 길게 모여 있던 `BookingActivity`의 입력을 Figma 환자 예약 화면의 단계 위계로 바꾸되, 이미 운영 경로에 연결된 예약 생성·수정·초안 복구 계약은 그대로 유지한다.

## 디자인 기준

- Figma 파일: `NX07k3Tu4cLc6YgAV82RXp`
- 페이지: `Page 1` (`0:1`)
- 구현 node: 환자 예약 `8:305`
- 확인 방식: 2026-09-27 `get_design_context`로 코드 컨텍스트와 스크린샷을 함께 조회했다.
- 기준 화면: 390×1657, 상단 앱바와 제목, 병원 검색·지도, 방문 날짜·시간, 요청사항, 주 CTA와 하단 탭 위계를 사용한다.

## 구현한 대응

| Figma 영역 | Android 대응 |
| --- | --- |
| 병원 검색 | 기존 `BookingHospitalSelectorActivity` 결과를 유지하고 선택 전에는 검색 문구, 선택 후에는 병원·진료과 요약을 표시한다. |
| 병원 지도 | 선택 결과에 실제 위·경도가 있을 때만 Kakao 지도와 병원 마커를 표시한다. 좌표가 없는 직접 입력은 안내 상태로 남긴다. |
| 날짜·시간 | 기존 `BookingAppointmentSelectorActivity`와 빠른 선택 버튼을 유지하고 Figma형 날짜·시간 요약 카드를 추가했다. |
| 건강 정보 | 기존 `BookingHealthProfileActivity` 결과와 필수 검증을 그대로 사용하고 별도 단계 카드로 분리했다. |
| 연결 대상 | 기존 이름·전화·이메일 필드와 환자/보호자 역할별 문구를 유지했다. |
| 동행 조건·결제 | 기존 이동 보조, 편도/왕복, 성별 선호, 결제, 쿠폰과 금액 계산 계약을 유지했다. |
| 요청사항·CTA | 숨겨져 있던 실제 `specialNotes` 입력을 Figma형 메모 영역으로 노출하고 기존 결제 승인 뒤 생성·수정하는 CTA에 연결했다. |
| 하단 탭 | 공용 사용자 하단 내비게이션의 `예약 내역` 탭 문구와 라우팅을 재사용했다. |

## 보존한 계약

- 병원, 날짜, 건강 정보, 만남 위치 선택 화면의 `ActivityResultLauncher`와 반환 파싱을 바꾸지 않았다.
- 선택 화면을 다녀올 때 `preserveFormOnNextDashboardBind`가 입력을 보존하는 흐름을 유지했다.
- `BookingFormBinder.buildDraft()`의 필수 필드, 가격 계산과 `BookingRequestDraft` 필드 구성을 유지했다.
- 생성과 수정은 모두 기존 결제 승인 화면을 통과하고, 취소·최근 예약·예약 내역 조회 경로도 유지했다.
- Figma node에 없는 신청자·최근 예약·수정·취소 카드는 기능을 삭제하지 않고 신청 CTA 아래의 기존 관리 영역으로 유지했다.
- 운영 `BookingActivity`의 저장소는 여전히 `ServiceLocator`를 사용한다. 다만 protected provider 훅으로 감싸 debug 전용 화면이 로컬 저장소를 주입할 수 있게 했다.

## 의도적으로 제외한 항목

- Figma의 선택 약국은 현재 `BookingRequestDraft`, Core API 또는 저장 모델에 필드가 없으므로 저장되지 않는 입력을 추가하지 않았다.
- 서버가 제공하지 않는 시간대별 실시간 예약 가능 여부를 만들지 않았다. 날짜·시간은 기존 선택·형식 검증만 사용한다.
- 좌표가 없는 병원에 임의 좌표나 검색 추정 좌표를 표시하지 않는다.
- 영문 예시 탭 이름 대신 현재 제품의 한국어 공용 탭과 라우팅을 유지했다.

## 설계 판단

- 작업 목적: Figma와 다른 예약 메인 시각 구조를 실제 운영 예약 흐름에 적용한다.
- 선택한 방식: Activity에는 화면 전환과 저장소 연결만 두고, 선택 결과 요약·날짜 포맷·지도 표시·inset 처리를 작은 객체로 분리했다.
- 대안: Figma 화면별로 예약 DTO를 임시 저장하는 여러 Activity를 새로 만들거나 한 번에 서버 계약을 확장하는 방식을 검토했다.
- 선택 이유: 현재 MVP에서는 검증된 단일 초안과 보조 선택 Activity를 유지하는 편이 입력 유실과 생성·수정 회귀 위험이 작다.
- 리스크: 긴 단일 스크롤이므로 작은 기기의 추가 시각 검증이 필요하다. 날짜·시간 카드는 고정 높이 대신 최소 높이를 사용해 큰 글꼴에서 확장되게 했다. Kakao 지도 렌더링은 유효한 앱 키와 실제 좌표가 있는 실행 환경에서 종단 확인해야 한다.

## 남은 범위

- debug 예약 미리보기에서 긴 스크롤, 키보드, 하단 탭과 시스템 inset을 실기기로 확인한다. 이 미리보기는 Kakao 지도 SDK를 시작하지 않는다.
- 실제 병원 선택 결과로 Kakao 지도 마커와 카메라 이동을 확인한다.
- 기획과 API가 승인되기 전까지 선택 약국과 실시간 가능 시간은 화면에 추가하지 않는다.
