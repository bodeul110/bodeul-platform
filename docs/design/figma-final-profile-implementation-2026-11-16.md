# 피그마 완성본 마이페이지·설정 반영

## 설계 판단

- 작업 목적: 채팅 상세 다음 순서인 일반·매니저 마이페이지와 설정 진입 메뉴를 완성본으로 맞춘다.
- 선택한 방식: 기존 인증·역할을 기준으로 공통 메뉴를 표시하고, 계정 정보·건강정보·문의·서류·이력 화면의 기존 기능은 그대로 연결한다.
- 대안: 모든 계정·결제·문의 저장 계약까지 한 번에 교체하거나 기존 상세 관리 화면을 제거하는 방안을 검토했다.
- 선택 이유: 현재 규모에서는 검증된 저장 경계를 유지하며 진입 화면부터 바꾸는 편이 기능 회귀와 배포 위험이 작다.
- 리스크: 사진·다중 역할·출금·카드 저장·공지 CMS 계약이 없는 상태에서 피그마 예시값을 실제 데이터로 표시하지 않는다. 해당 메뉴는 미연결 안내를 제공한다.

## 원본과 범위

- 파일: [보들 완성본](https://www.figma.com/design/fqwi44prjEgVFZhaM6LuzS?node-id=1-7645)
- 일반 마이페이지 `1:7645`, 사진 없는 상태 `1:7692`, 매니저 마이페이지 `1:7789`, 설정 `1:3382`, 프로필 편집 `1:4286`.
- 공통 Pretendard·브랜드색·여백을 재사용한다. #510에서 승인된 필수 글자 대비 보완과 Android 시스템 안전영역·48dp 터치 영역을 유지한다.
- 이름·이메일·앱 버전은 실제 계정과 빌드값을 표시한다. 프로필 사진은 원본의 사진 없는 상태를 사용한다.
- 이름 변경 상세 `1:16918`은 본인인증 후 인증된 이름으로 변경하는 계약이다. 기존 로그인 직후 프로필 보완 API를 일반 이름 변경에 재사용하지 않는다. 편집 진입에서는 기존 계정 정보를 확인하고 미연결 상태를 안내한다.
- 관리자 웹·Core API·DB·의존성·운영 배포는 변경하지 않는다.

Android 11(API 30) 에뮬레이터의 표시 환경:

건강정보 대화상자 버튼은 2배 글꼴에서 긴 기존 문구가 잘리는 것을 확인해 짧은 `건강정보`로 보완했다. 원본의 좁은 버튼 치수보다 48dp 터치 영역을 우선하고, 역할 선택 글자는 확대해도 한 줄이 유지되도록 최소 폭과 내용 폭을 함께 사용한다.

`ClientNavigationReturnTest.submittedBooking_realKeyboardAndAllTabs_keepNavigationBounds`는 새 프로필 진입 전 `BookingActivity`에서 하단 메뉴가 보인다고 가정해 실패한다. 별도 깨끗한 기준 커밋 APK를 같은 에뮬레이터에 설치했을 때도 동일하게 재현했다. 현재 단계형 예약은 하단 탭을 숨기므로, 이 테스트의 전체 예약 진행·키보드 확인 절차는 별도로 최신화해야 한다. 이번 작업에서 검사 조건을 삭제하거나 예약 동작을 바꾸지 않았다.

로컬 증적은 `.tmp/figma-profile/`의 빌드·계측·기준 비교 로그와 `captures/`의 합성 계정 화면이다. 실제 계정·기기 정보는 캡처하지 않았다. 이 임시 산출물은 커밋하지 않는다.

## 남은 범위

- 이름 변경의 본인인증, 프로필 사진 저장, 동일 계정의 다중 역할 전환은 별도 인증·데이터 계약이 필요하다. 현재는 계정 조회와 미연결 안내만 제공한다.
- 수익금·정산·출금, 저장된 결제수단, 공지·FAQ 목록·약관 원문 계약은 연결하지 않았다. `0원`, 빈 목록, 완료 메시지로 성공을 꾸미지 않는다.
- 설정의 결제정보·계정설정·알림설정 상세 및 고객센터·문의 목록/작성, 매니저 서류 관리 화면 자체의 완성본 스타일은 후속 화면 단위다. 이번에는 마이페이지·설정 진입 메뉴와 기존 기능 연결을 변경했다.
- 실제 개발 계정으로 로그인·설정 왕복·문의·서류·리포트 접근을 확인하는 실기기 리허설은 남아 있다.
