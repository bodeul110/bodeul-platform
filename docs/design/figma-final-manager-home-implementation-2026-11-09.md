# 피그마 완성본 매니저 홈 반영

기준일: 2026-11-09

## 설계 판단

- 작업 목적: [완성본 매니저 홈](https://www.figma.com/design/fqwi44prjEgVFZhaM6LuzS?node-id=1-7071)의 시각 체계에 맞추면서 기존 동행·서류·일정 메모·문의 경로를 유지한다.
- 선택한 방식: 공통 Pretendard·색상·원본 이미지와 고정 상하단 구조를 재사용한다. 본인 배정 목록은 기존 Core API의 `/api/appointments`를 ManagerRepository 경계에서 읽고, 조회된 최대 100건의 집계와 날짜별 목록을 표시한다.
- 대안: 피그마 예시 숫자 고정, 완료 이력만으로 전체 집계 추정, 신규 매칭·통계 API 추가를 검토했다.
- 선택 이유: 현재 화면 반영 범위에서는 이미 인가된 읽기 계약을 재사용하는 것이 배포·데이터 전환 위험이 가장 작다. 예시 데이터나 일부 완료 이력은 실제 매칭 현황으로 표시할 수 없다.
- 리스크: 최대 100건은 전체 누적 통계가 아니다. 스스로 미배정 예약을 수락하는 계약과 프로필 사진 URL은 아직 없으므로 자동 매칭·임의 사진은 추가하지 않는다. 이 범위가 필요해지면 별도 API와 권한 검토가 필요하다.

## 구현 경계

- 홈: 인사말, 매칭 현황, 추가 서류 등록, 간편 보들백서, 5탭. 약관 원문과 공개 주소는 이번에 만들지 않는다.
- 캘린더·매칭: 본인에게 배정된 조회 내역만 읽기 표시한다. 기존 예약이나 세션을 수정하지 않는다.
- 현재 동행: 실제 활성 세션이 있을 때 기존 가이드 진입 영역을 추가한다. 동행 시작·진행·메모·종료 구현은 변경하지 않는다.
- 채팅·마이·문의·완료 이력·서류 등록: 기존 화면으로 연결한다. 일정 메모는 캘린더에서 기존 저장 경로를 유지한다.
- 데이터: 진행중은 배정 완료와 실제 진행 상태를 합친다. 완료·취소는 각각 실제 상태로 분리한다. 집계 로딩·실패는 숫자 0과 구분한다.
- 과거 Firestore 전용 저장소는 신규 목록 계약을 지원하지 않으면 명시적으로 조회 불가를 반환한다. Core API 오류를 Firestore 데이터로 조용히 대체하지 않는다.
- 비동기 응답은 화면 이탈·재조회 시 무효화한다. 인증/역할 오류에서는 이전 계정의 내용을 지운다.
- 일정 메모 조회에 실패하면 빈 편집창을 열지 않는다. 저장 중에는 중복 제출을 막고 실패 후 다시 시도할 수 있다.
- 관리자 웹, Core API 서버, DB 스키마·인가, 의존성과 운영 환경은 변경하지 않는다. 앱에서 기존 서버 읽기 계약을 호출하는 경로만 추가한다.

## 시각 예외

- 배치·브랜드색은 완성본을 우선한다. 이전에 승인한 필수 글자 대비 보완은 공통 최종 색상 기준으로 유지한다.
- 강조 문장은 원본과 같은 파란 계열의 고대비 글자색 `#006BBD`를 사용한다. 가장 진한 원본 하늘색 배경 `#C4F2FF`에서도 4.55:1 이상이다. 파란 매칭 헤더는 기존 검정 글자 토큰을 사용한다.
- 서류 바의 양 끝 검정·브랜드 파랑은 유지하고 글자 아래 중간 구간만 어둡게 한다. 실제 렌더링 배경의 글자 영역에서 4.5:1 이상을 검사한다.
- 원본의 작은 조작 영역은 Android 터치 영역 48dp 이상으로 확보한다. 원본에 없는 집계 범위 설명과 현재 동행 영역은 실제 정보와 기존 기능을 유지하기 위한 추가다.
- 예시 인물 사진은 사용하지 않고, 실제 사진 계약이 생기기 전까지 공통 프로필 아이콘을 사용한다.
- 원본 안내 이미지와 크롭을 유지하되 미구현 AI 매칭·임의 게시일을 사실처럼 표시하지 않는다.
- 약관 원문·동의 흐름의 공급은 후속 범위다. 하단에는 환자 홈과 같은 방식으로 실제 이용 가능한 완료 이력·문의·로그아웃을 유지한다. 원본의 약관 연결까지 완료했다고 보지 않는다.
- 알림 개수 계약이 없어 원본의 예시 배지 숫자는 넣지 않는다. 알림 버튼은 기존 문의·답변 화면을 연다.
- 시스템 상태바·제스처 영역은 실제 Android inset으로 처리한다. 피그마 iOS 상태바는 이미지로 넣지 않는다.

## 재사용 자산과 후속 화면

로고·알림·사진·공통 메뉴 13개는 이번 Figma 응답의 원본과 기존 환자 홈 자산의 SHA-256이 같음을 확인해 재사용했다. 매칭 메뉴만 새 원본 SVG에서 Android용 투명 PNG로 변환했다. 환자·매니저의 안내 카드 크롭과 고대비 확인 대화상자는 `FinalHomeNoticeBinder`로 공통화하고 환자 홈 회귀 검사를 함께 실행한다.

5탭 중 캘린더·매칭은 기존 본인 배정 조회 결과의 날짜·상태 필터부터 연결한다. 이 하위 화면 전체의 Figma 개편, 미배정 예약 수락·자동 매칭, 채팅방 목록·검색, 프로필 사진 업로드는 이번 홈 반영의 완료 범위가 아니다. 현재 동행의 가이드, 기존 단일 동행 채팅과 마이 화면은 그대로 연결된다.

## 검증

빌드·단위 테스트·화면 검증 결과와 실제 연동 검증의 한계는 [검증 보고서](../reports/figma-final-manager-home-validation-2026-11-09.md)에 기록한다. 운영 배포·실데이터 쓰기는 이번 작업에 포함하지 않는다.
