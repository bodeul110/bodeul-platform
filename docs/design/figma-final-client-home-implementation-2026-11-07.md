# Figma 완성본 환자 홈 반영

기준일: 2026-11-07. 기준 소스: #510 병합 후 `dev`의 `1aa8ba6`.

## 설계 판단

- 작업 목적: 완성본의 다음 순서인 환자·보호자 홈을 적용하면서 예약, 진행 조회, 리포트, 문의와 역할 인가를 유지한다.
- 선택한 방식: [홈 1:6666](https://www.figma.com/design/fqwi44prjEgVFZhaM6LuzS?node-id=1-6666)의 실제 자산·배치·글자를 Android 리소스로 옮긴다. 공통 5탭의 캘린더는 본인 예약 날짜 필터, 채팅은 기존 동행방으로 연결한다.
- 대안: 매니저 홈·예약 신규 필드·매칭 API를 동시에 교체하거나 홈만 정적 이미지로 만든다.
- 선택 이유: 현재 규모에서는 환자 홈과 이동 경계를 먼저 검증해야 기존 시연 흐름을 유지하면서 다음 화면을 독립적으로 반영할 수 있다.
- 리스크: 원본 예시의 알림 수, 게시일, AI 매칭 문구와 실제 데이터가 다르다. 실제 문의 알림 수와 기존 안내 콘텐츠를 사용하고 완료되지 않은 계약을 정상 기능으로 표시하지 않는다.

## 범위

- 원본 로고·배너 일러스트·아이콘·콘텐츠 썸네일, 375dp 기준 반응형 배치, 5탭.
- 예약 진입, 현재 예약/진행/종료 상태, 보호자 리포트, 건강 정보, 문의, 로그아웃 경로 보존.
- 홈의 위치·날짜·시간 영역은 기존 예약 폼 진입이다. 위치는 병원 선택이 선행되지 않았으면 병원 선택기를 먼저 열고, 날짜는 기존 날짜·시간 선택기를 연다. 시간은 `예약 폼에서 확인`으로 표시한다. 홈 자체에 입력 초안을 새로 만들거나 병원 예약 시각과 별도인 만남 시각을 저장하지 않으며, 기존 `appointmentAt`의 의미도 바꾸지 않는다.
- 필수 텍스트는 #510에서 승인한 대비 보완 원칙을 이어 적용한다. 브랜드 배경색과 자산은 바꾸지 않는다.
- 매니저 홈, 별도 만남 시각 계약, 자동 매칭, 실제 게시 콘텐츠/약관 원문 공급은 이번 완료 범위가 아니다.

## 원본과 연결 방식

| 항목 | 적용 |
| --- | --- |
| 자산 | 원본 로고, 배너, 알림·탭·화살표 아이콘, 안내 썸네일 4개를 사용한다. SVG는 Android 표시를 위한 4배율 PNG 형식 변환만 했으며 사진은 원본을 그대로 둔다. 두 사진의 크롭은 ImageView 배치로 처리한다. |
| 배치 | 상단 375dp 그라데이션, 15dp 좌우 여백, 예약·안내 카드, 64dp 하단 메뉴에 실제 시스템 안전영역을 더한다. 헤더·스크롤·메뉴가 서로 겹치지 않게 영역을 분리한다. |
| 읽기성 | #510의 승인된 원칙에 따라 힌트·부제·버튼 글자는 명암 대비를 보완한다. 브랜드 배경·원본 자산은 유지한다. `자세히 보기`는 원본 44dp보다 넓은 48dp 터치 영역을 확보한다. |
| 알림 | 예시 숫자 5 대신 실제 미확인 문의 답변 수를 표시한다. 오래된 미확인 답변 안내와 문의 진입도 보존한다. |
| 배너·백서 | 배너가 1개이므로 작동하지 않는 페이지 표시 점은 넣지 않는다. 백서는 실제 앱 안내 4개에 연결하며 가짜 게시일이나 미구현 AI 매칭을 노출하지 않는다. |
| 기존 사용자 기능 | 실제 예약이 있으면 원래 진행·일시·장소·4단계·완료 후속 정보·보호자 안내를 별도 진행 영역에서 표시한다. 건강정보·문의·로그아웃을 유지한다. |
| 약관 | 원문과 연결 계약이 없는 약관을 누를 수 있는 링크처럼 만들지 않는다. 기존 기능 링크를 보존하고 실제 약관 연결은 별도 범위로 둔다. |

## 화면 이동과 데이터 경계

- 공통 메뉴는 홈·캘린더·이용내역·채팅·마이다. 채팅과 마이는 기존 Activity·인가 경로를 그대로 사용한다.
- 캘린더는 기존 본인 예약 조회 결과를 서울 날짜로 필터링한다. 날짜가 없는 예약은 임의 날짜에 배치하지 않고 이용내역에서 확인하도록 안내한다. 결과가 없어도 날짜 선택은 유지한다.
- 캘린더는 별도 최상위 Activity로 열어 이용내역과 왕복할 때 같은 인스턴스가 종료되는 문제를 피한다. 날짜 필터와 선택 날짜 복원은 이번 범위이며, 캘린더 화면 자체의 완성본 전체 시각 개편은 이용내역 단계에서 이어간다.
- 새 홈의 예약 버튼은 항상 신규 예약 진입이며 기존 예약 상세/보호자 리포트는 진행 영역에서 연다. 날짜 선택기를 닫거나 화면을 재생성해도 자동 재진입하지 않는다.
- 화면 종료·재조회 이후 도착한 이전 응답은 무시한다. 인증 실패에는 기존 데이터나 메뉴를 남기지 않는다.
- Core API, DB, 관리자 웹, 권한, 보호자 예약 기능 플래그, 결제 계약과 의존성 버전은 변경하지 않는다.

## 검증

빌드·단위 테스트·화면 계측 및 캡처 결과는 [검증 보고서](../reports/figma-final-client-home-validation-2026-11-07.md)에 분리한다. 변경은 [PR #511](https://github.com/bodeul110/bodeul-platform/pull/511)에서 검토하며, 이 기록은 병합·배포 완료를 뜻하지 않는다.
