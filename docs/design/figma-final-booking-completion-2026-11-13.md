## 설계 판단

- 작업 목적: 날짜·시간·장소 선택 이후의 결제 확인과 신청 완료도 완성본의 시각 흐름에 맞춘다.
- 선택한 방식: 결제 확인은 `1:20083`의 흰 배경·헤더·하단 버튼, 완료는 `1:7289`/`1:7467`의 시트·확인 아이콘·예약 요약 구조를 적용한다. 기존 확인 결과와 서버 저장 경계는 유지한다.
- 대안: 카드·은행 등록과 자동결제, 별도 만남 시각까지 한 번에 변경하는 방식을 검토했다.
- 선택 이유: 현재 예약 계약을 보존하는 화면 단위 변경이 회귀를 분리하기 쉽다. 실제 결제 연동이 없는 시뮬레이션을 승인·입금 성공으로 보이게 하지 않는다.
- 리스크: 원본의 두 시각·사진·주소·자동결제·매칭 기한은 현재 응답과 일치하지 않는다. 예시를 실제 정보처럼 표시하지 않고 별도 계약 범위로 남긴다.

## 변경 범위

| 화면 | 구현한 내용 | 유지한 기능 |
| --- | --- | --- |
| 결제 확인 | 흰 배경, 뒤로 가기 헤더, 공통 글꼴·색상, 선택 수단·쿠폰·금액 요약, 스크롤과 분리된 하단 버튼 | 선택한 병원·진료과·일시·만남 장소, 수단별 안내와 동의, 확인 결과 반환·취소 |
| 신청 완료 | 상단 모서리가 둥근 시트, 70dp 확인 아이콘, 25sp/32sp 제목, 병원 요약·예약 정보, 56dp 이상 하단 확인 버튼 | 접수/수정 완료 구분, 실제 병원·진료과·연도를 포함한 날짜·시각·주의사항, 예약 내역 이동 |
| 상세·위치 진입 | 저장된 예약 ID로 상세 이동, 선택 병원의 좌표 또는 이름으로 지도 앱 열기 | 상세에서 뒤로 돌아오면 완료 시트 유지, 지도 앱이 없으면 안내. 현재 위치 권한·서버 위치 저장 없음 |
| 확대·접근성 | 긴 이름·주의사항 줄바꿈, 하단 시스템 영역과 버튼 분리, 48dp 이상 조작 영역, 구형 Android에도 제목 역할 제공 | 큰 글자에서 확인 버튼과 마지막 안내까지 도달. #510에서 승인된 필수 텍스트 대비 보완 유지 |

확인·상세 화살표는 원본 SVG를 PNG로 내보냈고, 기존 완성본 뒤로 가기·닫기 자산은 재사용했다. 화살표는 원본 화면처럼 오른쪽을 향하도록 drawable 회전으로 적용했다. 폰트·의존성·SDK 버전은 추가하거나 올리지 않았다.

주요 코드는 [결제 확인 Activity](../../app/src/main/java/com/example/bodeul/ui/booking/BookingPaymentApprovalActivity.java), [완료 Activity](../../app/src/main/java/com/example/bodeul/ui/booking/BookingCompletionActivity.java), [완료 모델 변환](../../app/src/main/java/com/example/bodeul/ui/booking/BookingCompletionCoordinator.java), [완료 snapshot](../../app/src/main/java/com/example/bodeul/ui/booking/BookingCompletionSnapshot.java)에 있다. UI 바인딩은 Binder, 인텐트 변환은 Snapshot, 시스템 여백 처리는 Insets에 둔다.

## 계약 보존

- 동의 전에는 확인 버튼이 비활성이고, 동의 후 화면을 재생성해도 체크와 버튼 상태가 일치한다. 다시 해제하면 비활성화된다. 알 수 없는 결제 수단은 복원 후에도 차단한다.
- 카드·간편결제·계좌이체 확인은 기존 `SIMULATED` 결과와 도메인의 `PENDING`을 유지한다. 실제 결제 승인 코드·입금 계좌를 만들지 않는다. 현장 결제는 `DEFERRED`, 뒤로 가기는 `RESULT_CANCELED`다.
- 완료 화면은 새 예약을 생성하거나 서버의 결제·매칭 상태를 변경하지 않는다. 접수 시 받은 결제 수단·상태·금액을 표시하고 최신 상태는 예약 상세에서 확인하도록 구분한다.
- 현재 단일 `appointmentAt`을 연도 있는 날짜와 시각으로 나누어 표시한다. 별도의 만남 시각을 추정하지 않는다. 파싱할 수 없는 기존 날짜 문자열은 그대로 유지한다.
- 병원 사진·주소는 현재 완료 snapshot에 없으므로 예시 사진·주소를 넣지 않는다. 현재 선택한 병원의 이름·좌표만 사용하며, 좌표가 비어 있거나 유효하지 않으면 이름 검색으로 연결한다.
- 원본의 최대 2일 매칭, 매칭 후 자동결제, 입금 기한을 서버 보장 없이 표시하지 않는다. 이 기능들의 제품 목표를 없앤 것이 아니라 별도 연동 범위로 남긴다.
- 서버·DB·관리자 웹·환경변수·운영 배포는 변경하지 않았다.

검증은 JDK 21, Android API 34 에뮬레이터와 합성 예약으로 진행했다. 실제 환자 데이터·결제·지도 앱은 테스트 대상으로 호출하지 않는다.

신규 검사는 동의 확인·취소·재생성, 4개 결제 수단과 미지원 수단, 결제 성공 오표시 방지, 모든 기존 결제 상태, 새 접수/수정, 윤년과 연도 표시, 누락 값·레거시 날짜, 인텐트 필드 보존, 상세·지도·예약 내역 이동, 긴 텍스트·하단 안전 여백을 포함한다. UI 테스트용 Activity는 `debug`에만 존재하며 외부로 노출하지 않는다.

검사 중 체크박스가 텍스트 전용 스타일의 비클릭 속성을 상속하던 문제와 완료 시트 아래의 투명 영역을 수정했다. 확대 문구 검사에서는 줄 끝 공백을 글자 잘림으로 오인하지 않도록 실제 그려지는 폭을 측정한다. 캡처는 스크롤 후 화면 합성까지 기다리며, 긴 주의사항 마지막 줄의 도달 여부도 검사한다.

로컬 증적은 `.tmp/completion-validation/`의 빌드·검사 로그와 화면 캡처다. 최종 이미지는 `standard-capture/`, `compact-capture/`, `wide-capture/`이며 완료 화면 상단·스크롤 후 결제 상태·긴 주의사항 마지막 줄·결제 동의를 열어 확인했다. 이 임시 폴더는 Git에 포함하지 않는다. `git diff --check`, 변경 텍스트 UTF-8, XML 파싱, 문서 상대 링크도 통과했다.
