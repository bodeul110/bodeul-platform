# 피그마 완성본 채팅 상세 반영

## 기준과 범위

- 기준: [보들 어플 완성본 채팅 상세 1:15194](https://www.figma.com/design/fqwi44prjEgVFZhaM6LuzS?node-id=1-15194).
- 시작점: 최종 리포트 #526이 병합된 `dev`의 `3c7feea7526391ba17bbd093012844d669571373`.
- 범위: Android 채팅 상세의 헤더, 동행/이용 상세 이동, 날짜 구분, 말풍선, 고정 입력창, 첨부와 화면 복원 검증.
- 기존 메시지 전송, 사진/PDF 첨부, 읽음 표시, 알림/Realtime 갱신 및 서버 인가는 유지한다. 서버·DB·의존성·운영 배포는 변경하지 않는다.

## 설계 판단

- 작업 목적: 카드형 채팅을 완성본의 대화 중심 화면으로 바꾸되 실제 동행 데이터를 유지한다.
- 선택한 방식: 기존 Coordinator/ViewModel/Repository 경계에 네이티브 XML 화면을 연결하고 입력창은 메시지 스크롤과 분리한다.
- 대안: 예시 대화·사진을 그대로 표시하거나 채팅 저장소와 UI를 동시에 재작성한다.
- 선택 이유: 현재 MVP 규모에서는 기존 전송·첨부 계약을 유지하는 편이 회귀 범위를 줄인다. 참여자 사진·시스템 이벤트 계약이 추가되면 해당 표시 모델만 확장한다.
- 리스크: 큰 글꼴·키보드·첨부 선택 시 입력창이 메시지를 가리거나 복원 중 중복 전송이 발생할 수 있다. 작은 화면, 재생성, 전송 실패/중복 클릭을 별도로 검증한다.

## 원본과 실제 데이터 연결

- 상대 이름, 역할, 동행 상태, 메시지, 시간, 읽음, 첨부는 실제 조회 결과만 표시한다.
- 현재 User 계약에는 프로필 사진이 없으므로 사진 예시 대신 이름 이니셜을 표시한다.
- 시스템 이벤트 계약이 없는 ‘동행이 시작되었습니다’ 문구는 생성하지 않는다.
- 원본의 중복 문구 ‘이용 상세이용 상세’는 ‘이용 상세’로 표시한다.
- 상태바·키보드는 Android 시스템 UI다. 장식용 iOS 키보드를 앱에 그리지 않는다.
- 브랜드 파랑은 유지하되 작은 필수 텍스트는 기존 대비 보완 원칙을 적용한다.

## 구현한 내용

- 흰색 헤더, 이름 옆 상태 배지, 연한 회색 대화 배경, 날짜 칩, 흰색/파란색 말풍선과 하단 고정 입력창을 적용했다. Pretendard와 기존 공통 색상 리소스를 재사용한다.
- 뒤로가기 이미지는 기존 완성본 자산을 재사용하고 카메라·더보기·전송 이미지는 해당 Figma 노드에서 내보낸 자산을 사용한다. 새로운 아이콘/이미지 라이브러리는 추가하지 않았다.
- 일반 글꼴의 텍스트 대화는 원본처럼 시각을 말풍선 옆에 둔다. 첨부 또는 글꼴 130% 초과에서는 시각을 아래에 배치한다. 실제 환자·보호자·매니저를 구별하기 위해 받은 메시지에는 보낸 사람 이름과 역할을 함께 표시한다.
- 날짜에는 연도를 포함하고 실제 읽음 결과를 마지막 보낸 메시지에 표시한다. 본문 줄바꿈, 첨부 이름, 사진 미리보기, PDF 열기와 최대 3개 첨부 계약을 유지한다.
- 버튼의 터치 영역은 48dp 이상이며 상단 보조 버튼의 배경은 위아래 여백으로 원본의 36dp 형태를 유지한다. 큰 글꼴에서는 헤더 제목을 16sp로 조정하고, 키보드를 열면 보조 버튼·배지·이니셜을 잠시 숨겨 입력 공간을 확보한다.
- 본문과 첨부 URI·이름·형식을 저장 상태에 보존하고 화면 재생성 시 복원한다. 전송 중 입력/추가/제거를 막고 실패하면 초안을 남긴다. 계정이 바뀌면 이전 계정 초안과 첨부는 지운다.
- 화면이 보이는 동안만 Realtime/보호자 폴링을 유지한다. 늦게 도착한 조회 응답을 무시하고, 인가·조회 실패 시 이전 대화를 숨긴다. 푸시 알림의 원문으로 이전 대화가 다시 표시되지 않게 한다.
- 매니저가 다른 동행에 재배정되어도 열어 둔 채팅의 작성 내용을 새 동행으로 보내지 않는다. 종료·취소 상태에서는 이전 기록만 표시하고 쓰기 동작을 막는다. 최종 인가는 기존 서버에서 수행한다.

### 화면 이동

| 동작 | 연결 |
| --- | --- |
| 매니저의 실시간 동행 현황 | 기존 `ManagerGuideActivity` |
| 환자·보호자의 실시간 동행 현황 | 현재 예약 ID의 `BookingStatusActivity`에서 실제 상태 확인 |
| 환자·보호자의 이용 상세 | 같은 예약의 `BookingStatusActivity` |
| 매니저의 이용 상세 | 조회된 환자·병원·예약 시각·매니저 정보를 보여주는 대화상자 |
| 더보기 | 새로고침, 동행 정보, 홈 이동 |
| 뒤로가기 / 홈 | 기존 back stack으로 복귀 / 이미 열린 홈을 재사용 |

완성본의 채팅 상세에는 하단 탭이 없으므로 채팅 화면에서는 제거했다. 홈·이용내역 등 기존 최상위 화면의 탭은 그대로다. 환자·보호자 전용 단계별 읽기 화면을 새로 구현한 것은 아니며, 그 화면의 서버·표시 계약은 별도 범위다.

## 변경된 범위

- Android `ui/chat/`의 화면·표시 모델·상태 관리, 해당 레이아웃/문자열/테마/이미지.
- 메모리 저장소를 주입하는 비공개 debug Activity와 계측 테스트, 내비게이션 회귀 테스트의 채팅 상세 조건.
- 서버 API, Firebase/Storage Rules, DB 스키마·데이터, 관리자 웹, 의존성 버전은 변경하지 않았다.

## 검증

실제 계정·서버 대신 메모리 저장소를 사용한 Android API 30 에뮬레이터 검증이다. 개인 휴대폰이나 운영 데이터는 변경하지 않았다.

| 검증 | 결과 |
| --- | --- |
| `assembleDebug assembleDebugAndroidTest testDebugUnitTest :app:verifyReleaseAppCheckClasspath` | 통과, 단위 테스트 484건, 실패/건너뜀 0건 |
| `node tools/android/check-environment-boundary.mjs` | 개발/운영 Core API·Realtime 혼합 차단 4건 통과 |
| 375 x 812dp, 글꼴 100%, 3버튼 | 채팅 14건 + 공통 내비게이션 inset 6건 + 실제 홈 복귀 1건, 총 21건 통과 |
| 360 x 640dp, 글꼴 200%, 3버튼 | 채팅 14건 통과 |
| 412 x 915dp, 글꼴 130%, 제스처 | 채팅 14건 통과 |

| `git diff --check`, 변경 파일 UTF-8/XML 검사 | 통과 |

계측 범위는 실제 이름/상태/날짜/읽음, 정상·실패·빈 메시지·중복 전송, 사진 디코딩과 인가된 첨부 열기 요청, 첨부만 전송, 선택 취소·제거·화면 재생성, 매니저/환자/보호자 경로, 계정 변경, 종료 후 쓰기 차단, Realtime의 늦은 응답, 알림의 방 구분, 큰 글꼴과 실제 키보드다. 외부 문서 뷰어 자체의 동작이나 서버 파일 업로드까지 검증한 것은 아니다.

전체 내비게이션 회귀 실행 29건 중 28건은 통과했고, 기존 `submittedBooking_realKeyboardAndAllTabs_keepNavigationBounds` 1건이 채팅에 진입하기 전 예약 화면의 하단 탭이 `GONE`인 상태에서 실패했다. `BookingActivity`는 이전 완성본 작업에서 이미 하단 탭을 숨기므로, 이 오래된 예약 통합 테스트의 갱신은 이번 채팅 구현과 분리한다. 최종 코드의 채팅 뒤로가기·홈 메뉴 복귀는 예약 생성에 의존하지 않는 별도 테스트로 통과했다.

일반 대화, 긴 본문, 사진, 첨부, 종료 상태, 오류/재시도, 실제 IME 캡처를 세 크기에서 확인했다. 캡처 27개는 로컬 `.tmp/figma-chat/chat-captures/`에 보관한다. `.tmp/figma-chat/test-375-final.log`, `test-360-final.log`, `test-412-final.log`는 최종 실행 결과이며 Git에 포함하지 않는다.

화면 검증을 다시 실행할 때는 debug 앱과 androidTest APK를 설치한 뒤 다음 계측 클래스를 사용한다. `captureChat`은 선택적인 캡처 파일 접두어다.

## 남은 범위

- 실제 개발 계정 두 개의 메시지 송수신, 서버 업로드/다운로드, 보호자 동의 철회와 종료 이후 서버 거부 응답, 실제 Push/Realtime 왕복 및 실기기 확인.
- 프로세스 강제 종료 후 복원, 외부 파일 공급자의 장기 URI 권한은 이번 화면 재생성 검증과 별개다.
- 전체 채팅방 목록·닉네임 검색, 프로필 사진, 서버 시스템 이벤트, 환자·보호자의 별도 읽기 전용 동행 단계 화면.
- `dev` 대상 PR의 구현·검증 기록이다. 병합·배포는 별도이며 전체 Figma 적용 완료를 뜻하지 않는다.
