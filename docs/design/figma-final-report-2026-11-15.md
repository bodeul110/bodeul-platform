# 피그마 완성본 최종 리포트

기준: 2026-11-15, `dev`의 `08d930a3`.

## 작업 목적과 판단

- 작업 목적: 완성본 최종 리포트의 정보 위계를 반영하고 기존 조회·약물 비교·종료 후 권한을 유지한다.
- 선택한 방식: 기존 역할별 Repository로 다시 조회하는 읽기 전용 화면과 공통 Binder를 두고, 보호자 목록의 완료 리포트에도 같은 표현을 사용한다.
- 대안: 보호자 화면만 꾸미거나 모든 역할이 동일한 새 보고서 API를 사용하도록 변경하는 방식을 검토했다.
- 선택 이유: 현재 규모에서는 기존 데이터 계약을 재사용하는 것이 안전하며, 매니저의 종료 후 진료 정보 제한을 바꾸지 않고 화면을 통일할 수 있다.
- 리스크: 새 진입 경로가 이전 계정의 데이터를 보이거나 서버에서 가린 의료 정보를 재구성하면 안 된다. 복귀·재생성·오류·지연 응답과 매니저 제한을 별도로 검증한다.

## 원본과 범위

- [매니저 최종 리포트](https://www.figma.com/design/fqwi44prjEgVFZhaM6LuzS?node-id=1-11317)
- [환자·보호자 최종 리포트](https://www.figma.com/design/fqwi44prjEgVFZhaM6LuzS?node-id=1-19303)
- 원본 화면과 구조를 직접 확인했다. Pretendard, 15dp 여백, 25sp 제목, 하늘색 헤더, 병원·진료과, 회색 본문, 진료·다음 방문·복약·매니저 전달사항을 적용한다.
- 환자 상태는 기존 신청 시 기록이며 종료 시 건강 상태로 표현하지 않는다. 체류시간·나이·성별·병원 주소·실제 사진은 조회 계약이 없어 시안의 예시로 채우지 않는다.
- 매니저는 기존 이력 API가 제공하는 완료 일지와 방문 정보만 본다. 종료 후 진료 상세 조회 권한을 추가하지 않는다.
- 건강 인사이트 자동 생성, PDF 파일 저장, 외부 공유는 데이터·동의·유출 방지 계약이 없는 별도 기능이다. 동작하지 않는 버튼이나 가짜 의료 조언을 추가하지 않는다.
- Core API·DB·Firebase Rules·의존성·운영 설정은 변경하지 않는다. PR·병합·배포는 별도다.

## 검증 계획

1. 완료/미완료, 리포트 없음·일부 값만 있음, 약물 비교 값 유지, 역할별 Repository 경로를 확인한다.
2. 새로고침·오류 재시도·재생성·복귀 시 인증 재확인·늦게 도착한 응답을 계측 검증한다.
3. 360/375/412dp와 확대 글꼴에서 긴 이름·본문·버튼 잘림 및 시스템 영역 겹침을 확인한다.
4. Android 빌드·단위 테스트·계측 테스트·Release App Check·환경 분리 검사를 수행한다.

검증 로그와 캡처는 로컬 `.tmp/final-report/`에 보관한다. `standard-final-tests.log`, `small-font2-final-tests.log`, `wide-font13-final-tests.log`, `gesture-final-tests.log` 및 `final-report-captures/*-final-*-viewport.png`가 최종 증적이다. 비밀값·실사용자 의료 데이터를 캡처에 사용하지 않았다.

## 변경된 범위

- 환자·보호자는 완료된 예약 상세의 **최종 리포트 보기**, 매니저는 완료 이력의 같은 버튼으로 진입한다. 보호자 목록의 완료 리포트도 공통 화면 구성으로 표시하며 기존 상세 이동을 유지한다.
- `FinalReportActivity`는 요청 ID만 전달받고 복귀·재생성 때 인증과 조회를 다시 한다. 이전 요청의 늦은 응답은 무시하며 로딩·인증 실패·조회 오류 시 기존 내용을 숨긴다.
- `RoleScopedFinalReportRepository`는 환자 예약 상세, 보호자 허용 목록, 매니저 본인 이력을 각각 이용한다. 접근 실패 시 다른 역할의 조회 경로로 우회하지 않는다.
- `FinalReportBinder`는 기존 진료·다음 방문·복약·약물 비교·완료 일지를 표현한다. 매니저의 종료 후 의료 조회 제한은 저장소와 표현 계층에서 유지한다.
- 리포트 재시도·새로고침·뒤로 가기, 계정 변경·재생성·지연 응답, 빈 값 재바인딩, 완료 상태별 진입과 기존 예약 취소·정산·이력 동작을 확인했다.
