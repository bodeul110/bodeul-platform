# 완성본 공통 스타일·로그인 반영

기준일: 2026-11-07

## 기준과 범위

사용자 결정에 따라 **최신 Figma가 기존 MVP보다 우선**한다. 원본은 `보들 어플 완성본`의 [로그인 1:13671](https://www.figma.com/design/fqwi44prjEgVFZhaM6LuzS?node-id=1-13671), [이메일 오류 1:14278](https://www.figma.com/design/fqwi44prjEgVFZhaM6LuzS?node-id=1-14278)이다. 원본 구조·치수·이미지를 읽고 Android Java/XML에 적용했다.

이번 범위는 공통 스타일 기반과 `LoginActivity`다. 홈·예약·5탭·매칭·9단계 흐름의 목표 변경은 [전체 반영 계획](figma-final-app-gap-plan-2026-11-07.md)에 따르며, 이번 로그인 변경을 앱 전체 완성본 적용으로 보지 않는다.

## 구현한 내용

| 항목 | 적용 |
| --- | --- |
| 공통 값 | 버튼 `#01A1FF`, 입력 배경 `#F2F5F8`, 보조 글자 `#545B68`, 오류 `#FF4D4D`, Pretendard Medium/Bold |
| 배치 | 좌우 15dp, 로고 영역 80dp, 입력 최소 50dp·간격 10dp, 주 버튼 최소 56dp·위 간격 20dp, 모서리 10dp |
| 첫 화면 | 원본의 뒤로 가기·로고·이메일/비밀번호·로그인·보조 링크·하단 3개 소셜 버튼. 기존 제목·요약 카드·역할 칩은 첫 화면에서 제거 |
| 오류 | 입력 오류는 빨간 글자와 중앙의 어두운 메시지. 메시지 원문·검증 규칙은 유지하고 접근성 상태 설명·읽기 시간 설정을 반영 |
| Android 영역 | 실제 상태바·내비게이션·키보드는 시스템 UI로 유지. ScrollView 바깥에 inset을 적용해 회원가입 버튼이 시스템 영역에 가려지는 문제 수정 |
| 적용 범위 | `Theme.Bodeul.FinalAuth`와 `final_*` 리소스를 로그인에 먼저 사용. 다른 화면의 기존 토큰·테마는 변경하지 않음 |

원본의 40dp 보조 버튼은 시각 높이를 유지하고 터치 높이만 48dp로 확보한다. 글꼴 확대 시 입력·버튼 높이는 내용에 맞춰 늘어나며 화면을 비율로 축소하지 않는다. iOS 상태바 높이를 Android에 강제하지 않는다.

## 유지한 인증 기능

- 이메일 로그인, 이름·전화·이메일·비밀번호 검증, 회원가입과 이메일 인증 안내, 성공 후 기존 `AuthFlowRouter` 이동을 유지한다.
- 환자·보호자 선택은 로그인/소셜 인증 직전 선택창으로 옮긴다. 회원가입에서는 기존 역할 칩을 사용하며 매니저·관리자 역할은 진입 시 고정한다. 서버에 전달하는 역할 계약은 바꾸지 않는다.
- 비밀번호 찾기 링크에서 재설정과 인증 메일 재전송을 선택한다. 재전송 60초 제한은 메뉴 재진입·화면 재생성 후에도 적용한다.
- Kakao·Google과 기존 플래그 기반 Naver의 Repository 호출 경로를 유지한다. 관리자는 기존대로 이메일 로그인만 허용한다.
- Apple 아이콘은 Figma 원본에 맞게 표시한다. 아직 제공자 연동이 없어 클릭 시 미연동 상태와 사용 가능한 로그인 수단을 안내한다. 실제 Apple 인증 구현 완료로 간주하지 않는다.
- Firebase 설정이 없는 Mock 빌드의 데모 안내·역할별 자동 입력은 기존처럼 남긴다. 실제 인증 화면의 레이아웃 검증에는 외부 계정이 없는 debug 전용 저장소를 사용한다.

## 설계 판단

- 작업 목적: 완성본 우선 결정을 코드와 기준 문서에 반영하면서 기존 인증 기능의 회귀를 방지한다.
- 선택한 방식: 화면 전용 테마와 재사용할 토큰·스타일을 추가하고 기존 인증 Repository를 그대로 연결한다. debug 전용 가짜 저장소로 화면과 요청 인자를 검사한다.
- 대안: 전역 테마 일괄 교체, 기존 MVP 배치 유지, 로그인 제공자·서버 계약까지 한꺼번에 교체하는 방법을 검토했다.
- 선택 이유: 현재 앱은 여러 역할·인증·예약 흐름이 연결돼 있다. 화면을 하나씩 전환하면 원본과의 차이와 기능 회귀를 좁은 범위에서 확인할 수 있다.
- 리스크: 미전환 화면과 스타일이 공존한다. Apple·SMS 등 신규 제공자 설정과 전체 회원가입 흐름 교체는 후속 작업이다. 원본 버튼의 흰 글자 대비 약 2.78:1은 임의 색상 수정 없이 원본 접근성 과제로 남긴다.

## 검증과 남은 범위

검증 결과는 [공통 스타일·로그인 검증](../reports/figma-final-login-validation-2026-11-07.md)에 기록한다. 실제 외부 로그인, 실기기, 개발 서버 종단 호출, 운영 배포 여부는 로컬 미리보기 검증과 구분한다. 서버·DB·인증 제공자 설정·의존성 버전은 이번 작업에서 변경하지 않는다.
