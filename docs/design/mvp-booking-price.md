# MVP 예약 요금 적용 범위

- 작업 목적: #27의 신규 예약 견적을 최신 MVP의 기본 2시간 40,000원과 맞추되 기존 결제 이력을 보존한다.
- 선택한 방식: 신규 예약의 기본가·최종가는 40,000원, 옵션 추가와 쿠폰 할인은 0원으로 계산한다. 이동 지원·동행 범위는 서비스 요청 정보로 유지하고 새 쿠폰 적용은 받지 않는다. 편집·조회·생성 재시도는 기존 가격 snapshot을 유지한다.
- 대안: 기본가만 바꾸고 기존 추가요금·쿠폰을 적용하면 같은 MVP 예약이 40,000원과 다른 금액으로 표시된다. 기존 예약까지 재계산하면 원장과 안내 금액이 달라진다.
- 선택 이유: 현재 MVP 규모에서는 미확정 추가 청구를 만들지 않는 고정 견적과 생성 시점 snapshot이 가장 단순하다. 추후 추가요금·쿠폰은 별도 가격 정책으로 도입할 수 있다.
- 리스크: 실제 수취 승인이나 운영 약관 확정은 아니다. 기존 무통장입금의 결제수단·금액 조건 변경 거부를 유지하고 자동 취소·환불·초과시간 청구는 추가하지 않는다. 신규 쿠폰을 보내는 구형 앱에는 명시적으로 오류를 반환한다.

## 입금 안내

제품 안내 원칙은 신청 후 24시간 이내 입금, 임박 예약은 운영자 별도 확인이다. 이 단계에서는 Android 안내를 추가하되 `paymentDueAt`이 없는 원장에 날짜를 임의 생성하거나 기존 원장의 기한을 역산하지 않는다. 서버·관리자 웹의 동일 기한 snapshot 및 실제 계좌 개방은 #27에서 별도로 확인한다. 실제 계좌가 없는 합성 모드에서는 송금하지 말라는 안내를 유지한다.

## 기존 예약과 관리자 웹

기존 예약의 금액 구성은 일반 정보 수정에서도 그대로 유지한다. 기존 쿠폰 코드는 조회·수정 재전송을 허용하되 다른 쿠폰으로 바꾸지는 못한다. 무통장입금의 동행 범위·이동 보조·쿠폰·결제수단은 생성 뒤 변경할 수 없다. 다른 결제 체험 예약도 수정 때문에 금액을 다시 청구하지 않는다.

관리자 웹은 저장된 예약·결제 원장의 금액을 읽으므로 가격 공식이나 API 응답 형식 변경은 필요하지 않다. DB migration, 과거 예약 backfill, 운영 배포·금전 수취는 이 변경에 포함하지 않는다.
