# MVP 예약 요금 적용 범위

- 작업 목적: #27의 신규 예약 견적을 최신 MVP의 기본 2시간 40,000원과 맞추되 기존 결제 이력을 보존한다.
- 선택한 방식: 신규 예약의 기본가·최종가는 40,000원, 옵션 추가와 쿠폰 할인은 0원으로 계산한다. 이동 지원·동행 범위는 서비스 요청 정보로 유지하고 새 쿠폰 적용은 받지 않는다. 편집·조회·생성 재시도는 기존 가격 snapshot을 유지한다.
- 대안: 기본가만 바꾸고 기존 추가요금·쿠폰을 적용하면 같은 MVP 예약이 40,000원과 다른 금액으로 표시된다. 기존 예약까지 재계산하면 원장과 안내 금액이 달라진다.
- 선택 이유: 현재 MVP 규모에서는 미확정 추가 청구를 만들지 않는 고정 견적과 생성 시점 snapshot이 가장 단순하다. 추후 추가요금·쿠폰은 별도 가격 정책으로 도입할 수 있다.
- 리스크: 실제 수취 승인이나 운영 약관 확정은 아니다. 기존 무통장입금의 결제수단·금액 조건 변경 거부를 유지하고 자동 취소·환불·초과시간 청구는 추가하지 않는다. 신규 쿠폰을 보내는 구형 앱에는 명시적으로 오류를 반환한다.

## 입금 안내

제품 안내 원칙은 신청 후 24시간 이내 입금, 임박 예약은 운영자 별도 확인이다. 이 단계에서는 Android 안내를 추가하되 `paymentDueAt`이 없는 원장에 날짜를 임의 생성하거나 기존 원장의 기한을 역산하지 않는다. 서버·관리자 웹의 동일 기한 snapshot 및 실제 계좌 개방은 #27에서 별도로 확인한다. 실제 계좌가 없는 합성 모드에서는 송금하지 말라는 안내를 유지한다.

## 기존 예약과 관리자 웹

기존 예약의 금액 구성은 일반 정보 수정에서도 그대로 유지한다. 기존 쿠폰 코드는 조회·수정 재전송을 허용하되 다른 쿠폰으로 바꾸지는 못한다. 무통장입금의 동행 범위·이동 보조·쿠폰·결제수단은 생성 뒤 변경할 수 없다. 다른 결제 체험 예약도 수정 때문에 금액을 다시 청구하지 않는다.

관리자 웹은 저장된 예약·결제 원장의 금액을 읽으므로 가격 공식이나 API 응답 형식 변경은 필요하지 않다. DB migration, 과거 예약 backfill, 운영 배포·금전 수취는 이 변경에 포함하지 않는다.

## 앱·서버 배포 순서 보호

- 작업 목적: 앱과 서버의 업데이트 순서가 달라도 사용자가 확인한 요금과 다른 신규 예약이 저장되지 않게 한다.
- 선택한 방식: 새 앱은 `POST /api/appointments/price-confirmed`로 `pricePolicyVersion=mvp-fixed-40000-v1`과 화면 견적의 `expectedFinalPrice`를 보낸다. 서버는 신규 저장 전에 정책 버전과 40,000원을 검사한다. 기존 생성 경로도 같은 검사를 거치되 이미 저장된 동일 요청의 재시도는 먼저 반환한다.
- 대안: 최소 앱 버전은 현재 모두 `versionCode=1`인 설치본을 구분하지 못한다. 헤더만 추가하거나 GET 사전 검사 뒤 기존 POST로 보내면 구형 서버나 롤백 서버가 미지원 필드를 무시하고 다른 금액을 저장할 수 있다.
- 선택 이유: 현재 고정요금 MVP에서는 별도 생성 경로와 명시적 가격 계약으로 양방향 호환성을 확인하는 것이 단순하다. 새 앱·구형 서버 조합은 경로 없음으로 중단하고, 구형 앱·새 서버 조합은 가격 계약 누락으로 신규 생성을 거부한다. 앱은 기존 POST로 우회하지 않는다.
- 리스크: 서로 맞는 앱·서버가 준비될 때까지 신규 예약이 잠시 불가능하다. 이 값은 인증 수단이 아니며 Firebase 인증·서버 인가를 그대로 적용한다. 새로운 가격 정책을 도입할 때 버전도 바꿔야 한다.

기존 예약 조회·수정·취소는 경로와 가격 snapshot을 유지한다. 동일 `clientRequestId`와 원래 예약 내용이 확인되는 재시도는 가격 확인 필드가 없는 구형 앱에서도 기존 69,000원·96,000원 결과를 반환한다. 가격 확인 필드는 원래 요청 지문에 소급 추가하지 않는다. 다른 예약 내용이나 다른 사용자의 요청으로 기존 결과를 재사용할 수는 없다.

Android는 실제 화면에서 작성한 `priceSummary.finalPrice`를 보내며 서버 가격으로 조용히 대체하지 않는다. 구형 서버의 404/405에서는 업데이트 준비 안내만 표시하고 생성 경로를 바꾸지 않는다. 연결 오류 재시도는 같은 경로·요청 ID·금액을 유지한다.

관리자 웹과 DB 계약은 바꾸지 않는다. 소스 병합 후 개발 자동 배포가 새 요금도 포함한다는 점을 리뷰에서 확인하고, 같은 후보의 앱 설치·개발 API·원장·관리자 조회 정합성을 별도 검증한다. 운영 배포·실제 송금·환불 권한은 이 계약 도입에 포함되지 않는다.
